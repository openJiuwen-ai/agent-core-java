# 常见测试失败模式

本参考用于缩小调查范围，不是自动归因表。任何模式都必须结合 PR diff、测试契约和实际
调用链验证。

## 值或结构不匹配

典型证据：`expected ... but was ...`、集合元素差异、JSON 字段变化、字符串前后缀变化。

检查：

- 先提取最小差异，不逐字复制超长值；
- 追踪差异由哪个序列化、模板、聚合或默认值方法产生；
- 查看 PR 是否改变了返回值、字段顺序、过滤或完成逻辑；
- 确认断言代表公开契约还是实现细节。

## 空值、参数和类型异常

典型证据：`NullPointerException`、`IllegalArgumentException`、`ClassCastException`、
`IndexOutOfBoundsException`。

检查首个项目代码帧、输入构造、判空/校验顺序以及 PR 新增字段的初始化。异常抛出点
不一定是根因点，继续向上追踪错误值从哪里进入。

## 编译失败

区分：

- 产品源码编译失败；
- 测试源码编译失败；
- 依赖或插件无法解析；
- JDK/API 版本不匹配。

编译错误不能当作 TDD 的预期 RED。定位首个编译器错误，后续大量 symbol-not-found
可能只是级联。

## 测试发现失败

典型证据：`No tests were executed`、选择器不匹配、测试类未发现。

检查类名和包名、Surefire 选择器、JUnit 引擎、标签和测试可见性。没有执行测试不等于
测试通过，也不应归为产品行为失败。

## 超时、异步和流式未完成

检查：

- 完成事件、终止标志和回调是否仍会触发；
- PR 是否改变调度、锁、重试或流式完成判据；
- 测试是否使用固定 sleep 或过窄超时；
- 是否存在外部服务等待、线程泄漏或资源饥饿证据。

不要直接建议增加超时；先证明是合理耗时增长还是永不完成。

## 环境和依赖

典型证据：连接拒绝、DNS/TLS 错误、文件不存在、离线构件缺失、容器权限、OOM、线程
创建失败、错误 JDK 或本地服务未启动。

如果 PR 改变了端点选择、路径解析、证书加载或依赖坐标，环境表象可能仍由开发改动
引起。只有与 PR 无因果关系的真实环境差异才归为环境问题。

## 并发和偶发失败

典型证据：重复运行结果不同、顺序相关、共享静态状态、端口冲突、竞态或随机种子变化。

检查失败频率、执行顺序、并发测试、共享缓存和时间依赖。一次重跑通过只能证明可能
flaky，不能证明原失败无效。

## 负向验证和刻意注入

PR 名称、描述或 diff 可能明确注入失败以验证流水线。先确认该意图与授权来源，再将
结果记录为“验证按预期捕获失败”。建议关闭或回退注入变更，不为其设计永久产品补丁。

## 级联失败

初始化、公共 fixture、应用上下文或共享服务的单点失败可能导致大量测试同时报错。找出
最早失败和共同项目帧，将后续失败标记为级联影响，避免重复给出相互矛盾的修复建议。
