# 动态传入模型使用指南

> 适用版本: v0.1.16+
> 相关 Issue: [#74](https://gitcode.com/openJiuwen/agent-core-java/issues/74)
> 设计文档: [issue-74-dynamic-model-config.md](../../../docs/design/issue-74-dynamic-model-config.md)

## 概述

DeepAgent 支持配置多个模型并在每次请求时动态切换，实现单实例多模型并发。本文档介绍如何配置多模型、编写自定义 Rail 选择模型，以及并发使用场景。

**核心能力**:

- 一个 DeepAgent 实例配置多个模型，其中一个为默认模型
- 每次 `invoke` 时动态指定使用哪个模型
- 多用户并发调用不同模型，互不干扰
- Context 处理器（压缩/摘要）使用的模型与请求指定的模型一致

## 快速开始

### 1. 配置多模型

通过 `DeepAgentConfig.modelConfigs` 配置多个模型：

```java
DeepAgentConfig config = DeepAgentConfig.builder()
    .systemPrompt("你是智能助手。")
    .workspacePath("./workspace")
    .modelConfigs(List.of(
        ModelConfigEntry.builder()
            .modelId("deepseek-v4")
            .isDefault(true)
            .modelConfig(ModelRequestConfig.builder()
                .modelName("deepseek-v4-flash")
                .temperature(0.7)
                .maxTokens(8192)
                .build())
            .modelClient(ModelClientConfig.builder()
                .clientProvider("OpenAI")
                .apiKey("sk-deepseek-xxx")
                .apiBase("https://api.deepseek.com/v1")
                .build())
            .build(),
        ModelConfigEntry.builder()
            .modelId("glm-5.1")
            .isDefault(false)
            .modelConfig(ModelRequestConfig.builder()
                .modelName("glm-5.1")
                .temperature(0.7)
                .maxTokens(8192)
                .build())
            .modelClient(ModelClientConfig.builder()
                .clientProvider("OpenAI")
                .apiKey("sk-glm-xxx")
                .apiBase("https://open.bigmodel.cn/api/paas/v4")
                .build())
            .build()
    ))
    .rails(List.of(new TopLevelModelIdRail()))
    .build();
```

### 2. 动态选择模型

DeepAgent 支持通过 `model_id` 在每次 `invoke` 时动态指定使用的模型。框架支持两种 carrier 方式传递 `model_id`，业务 Rail 从对应位置提取后调用 `ctx.setDynamicModelId(modelId)`，框架的 `getLlm(ctx)` 会自动解析。

#### 2.1 方式一：model_id 放在顶层（推荐）

将 `model_id` 放在 `invoke` 输入的顶层。框架会自动将其透传到 `ctx.getExtra().get("model_id")`，业务 Rail 从 `ctx.getExtra()` 中提取。

**invoke 示例**：

```java
DeepAgent agent = HarnessFactory.createDeepAgent(card, config, workspace);
agent.ensureInitialized();

// model_id 放在顶层，框架透传到 ctx.extra
agent.invoke(Map.of("query", "解释量子计算", "model_id", "deepseek-v4"));

// 不指定 model_id，使用默认模型
agent.invoke(Map.of("query", "你好"));
```

**Rail 示例**：

```java
public class TopLevelModelIdRail extends DeepAgentRail {

    @Override
    public int priority() {
        return 90; // 在 ContextProcessorRail(85) 之前执行
    }

    @Override
    public void beforeInvoke(AgentCallbackContext ctx) {
        // 从 ctx.getExtra() 中提取顶层 model_id
        if (ctx.getExtra() != null) {
            Object modelId = ctx.getExtra().get("model_id");
            if (modelId instanceof String id && !id.isBlank()) {
                ctx.setDynamicModelId(id);
            }
        }
    }
}
```

#### 2.2 方式二：model_id 嵌套在 query 对象中

将 `model_id` 嵌套在 `query` 对象中（即 `query` 是一个 Map）。`query` 的值成为 `queryPayload`，业务 Rail 从 `queryPayload` 中提取 `model_id`。

**invoke 示例**：

```java
DeepAgent agent = HarnessFactory.createDeepAgent(card, config, workspace);
agent.ensureInitialized();

// model_id 嵌套在 query Map 中
agent.invoke(Map.of("query", Map.of("text", "解释量子计算", "model_id", "deepseek-v4")));

// 不指定 model_id，使用默认模型
agent.invoke(Map.of("query", Map.of("text", "你好")));
```

**Rail 示例**：

```java
public class NestedModelIdRail extends DeepAgentRail {

    @Override
    public int priority() {
        return 90; // 在 ContextProcessorRail(85) 之前执行
    }

    @Override
    public void beforeInvoke(AgentCallbackContext ctx) {
        // 从 queryPayload 中提取嵌套的 model_id
        if (ctx.getInputs() == null) {
            return;
        }
        Object payload = ctx.getInputs().getQueryPayload();
        if (payload instanceof Map<?, ?> map) {
            Object modelId = map.get("model_id");
            if (modelId instanceof String id && !id.isBlank()) {
                ctx.setDynamicModelId(id);
            }
        }
    }
}
```

#### 2.3 默认

不指定 `model_id` 时，使用 `modelConfigs` 中 `isDefault=true` 的默认模型。`query` 可以是纯字符串或 Map。

```java
// query 为字符串，使用默认模型
agent.invoke(Map.of("query", "你好"));

// query 为 Map 但不含 model_id，使用默认模型
agent.invoke(Map.of("query", Map.of("text", "你好")));
```

> **提示**: 两种 carrier 方式的 Rail 提取逻辑不同。如果需要同时支持两种 carrier，可在 Rail 中先检查 `ctx.getExtra()` 再检查 `queryPayload`。

## 模型解析优先级

框架通过 `getLlm(ctx)` → `ModelMgr.resolveModel()` 统一解析模型，优先级由高到低：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | `ctx.dynamicModelId` | 当前请求动态指定的模型 ID，通过 ModelMgr.resolveModel 解析 |
| 2 | 已注入的 `llm` 实例 | 通过 `setLlm()` 注入或已懒加载的 Model 实例 |
| 3 | ModelMgr 默认模型 | 当 `llm` 为 null 且无 `modelClientConfig` 时，通过 ModelMgr 获取默认模型 |
| 4 | 懒加载 | 从 `config.modelClientConfig` + `config.modelConfigObj` 构建（可能抛异常） |

> **注意**: 当 `dynamicModelId` 为 null 时，优先返回 `setLlm()` 注入的实例（保持向后兼容）。
> 只有在 `llm` 为 null 且 agent 没有配置 `modelClientConfig` 时，才通过 ModelMgr 获取默认模型。

## 配置方式

### 方式一：modelConfigs（推荐）

直接在 `DeepAgentConfig` 中配置 `modelConfigs` 列表：

```java
DeepAgentConfig.builder()
    .modelConfigs(List.of(
        ModelConfigEntry.builder()
            .modelId("model-a").isDefault(true)
            .modelConfig(...).modelClient(...).build(),
        ModelConfigEntry.builder()
            .modelId("model-b").isDefault(false)
            .modelConfig(...).modelClient(...).build()
    ))
    .build();
```

**校验规则**:

- `modelId` 不可重复，否则抛 `IllegalArgumentException`
- 有且仅有一个 `isDefault=true`；若无，自动将第一个设为默认
- 多个 `isDefault=true` 时抛 `IllegalArgumentException`
- `modelId` 为空白时自动生成 `modelName@provider` 格式 ID

### 方式二：model + backend（兼容旧配置）

保持原有的 `model` + `backend` 单模型配置方式。框架在构造时自动合并到 `modelConfigs`：

```java
DeepAgentConfig.builder()
    .model(ModelRequestConfig.builder().modelName("deepseek-v4").build())
    .backend(ModelClientConfig.builder()
        .clientProvider("OpenAI").apiKey("sk-xxx").apiBase("...").build())
    .build();
```

### 方式三：YAML 配置文件

```yaml
deepAgents:
  - name: myAgent
    modelConfigs:
      - modelId: deepseek-v4
        isDefault: true
        modelConfig:
          modelName: deepseek-v4-flash
          temperature: 0.7
        modelClient:
          clientProvider: OpenAI
          apiKey: "sk-deepseek-xxx"
          apiBase: "https://api.deepseek.com/v1"
      - modelId: glm-5.1
        isDefault: false
        modelConfig:
          modelName: glm-5.1
          temperature: 0.7
        modelClient:
          clientProvider: OpenAI
          apiKey: "sk-glm-xxx"
          apiBase: "https://open.bigmodel.cn/api/paas/v4"
    rails:
      - com.example.TopLevelModelIdRail
```

## 自定义 Rail 编写指南

### beforeInvoke vs beforeModelCall

| 钩子 | 执行时机 | 影响范围 |
|------|---------|---------|
| `beforeInvoke` | 请求开始时执行一次 | 对整个请求的所有模型调用生效 |
| `beforeModelCall` | 每次 `model.invoke()` 之前执行 | 可逐次调用设置不同模型 |

**推荐**: 在 `beforeInvoke` 中设置 `dynamicModelId`，对整个请求生效。如需逐次调用切换模型，在 `beforeModelCall` 中设置。

### 完整 Rail 示例

以下 Rail 同时支持两种 carrier（顶层优先，嵌套兜底），适合需要兼容多种调用方式的场景：

```java
import com.openjiuwen.core.singleagent.rail.AgentCallbackContext;
import com.openjiuwen.harness.rails.DeepAgentRail;

public class DynamicModelSelectRail extends DeepAgentRail {

    @Override
    public int priority() {
        return 90; // 需大于 ContextProcessorRail(85)
    }

    @Override
    public void beforeInvoke(AgentCallbackContext ctx) {
        String modelId = resolveModelId(ctx);
        ctx.setDynamicModelId(modelId);
    }

    private String resolveModelId(AgentCallbackContext ctx) {
        // 优先：顶层 model_id（框架透传到 ctx.extra）
        if (ctx.getExtra() != null) {
            Object topId = ctx.getExtra().get("model_id");
            if (topId instanceof String id && !id.isBlank()) {
                return id;
            }
        }
        // 兜底：嵌套 model_id（从 queryPayload 提取）
        if (ctx.getInputs() != null) {
            Object payload = ctx.getInputs().getQueryPayload();
            if (payload instanceof Map<?, ?> map) {
                Object nestedId = map.get("model_id");
                if (nestedId instanceof String id && !id.isBlank()) {
                    return id;
                }
            }
        }
        return null; // null = 使用默认模型
    }
}
```

### beforeModelCall 覆盖示例

```java
public class PerCallModelRail extends DeepAgentRail {

    private int callCount = 0;

    @Override
    public int priority() {
        return 95; // 在 ContextProcessorRail(85) 之后也能覆盖
    }

    @Override
    public void beforeModelCall(AgentCallbackContext ctx) {
        // 偶数次用 m2，奇数次用 m1
        String modelId = (callCount++ % 2 == 0) ? "model-b" : "model-a";
        ctx.setDynamicModelId(modelId);
    }
}
```

## 并发场景

单实例 DeepAgent 支持多用户并发调用不同模型：

```
用户A invoke(query="...", model_id="deepseek-v4")
  → Thread-1: Rail.beforeInvoke → ctx.setDynamicModelId("deepseek-v4")
  → Thread-1: getLlm(ctx) → ModelMgr.resolveModel("deepseek-v4", ...) → deepseekModel
  → Thread-1: model.invoke() → 调用 DeepSeek API

用户B invoke(query="...", model_id="glm-5.1")  (并发)
  → Thread-2: Rail.beforeInvoke → ctx.setDynamicModelId("glm-5.1")
  → Thread-2: getLlm(ctx) → ModelMgr.resolveModel("glm-5.1", ...) → glmModel
  → Thread-2: model.invoke() → 调用 GLM API
```

**线程安全保证**:

- `getLlm(ctx)` 是无状态的，不修改任何实例字段
- `ModelMgr` 内部使用 `ConcurrentHashMap` 存储模型 Supplier
- 每个 `AgentCallbackContext` 是请求级隔离的
- `Model` 实例本身无状态，多线程共享安全

## 模型运行时管理

### 更新模型

```java
// 更新已有模型配置（覆盖 supplier）
Supplier<Model> newSupplier = () -> new Model(newClientConfig, newRequestConfig);
Runner.resourceMgr().updateModel("deepseek-v4", newSupplier, Tag.GLOBAL);
```

更新后通过 EventBus 发布 `ModelUpdatedEvent`，`ContextProcessorRail` 自动失效对应的 ProcessorSpec 缓存。

### 删除模型

```java
// 删除模型（生产环境：至少保留一个模型）
Runner.resourceMgr().removeModel("glm-5.1", Tag.GLOBAL, TagMatchStrategy.ALL, true);

// 测试环境：强制删除最后一个模型
Runner.resourceMgr().removeModelForce("glm-5.1", true);
```

删除后通过 EventBus 发布 `ModelRemovedEvent`，自动清除缓存。如果删除的是默认模型，自动将剩余的第一个模型设为新默认。

### 列出已注册模型

```java
List<String> modelIds = Runner.resourceMgr().listModelIds();
```

### 设置默认模型

```java
Runner.resourceMgr().setDefaultModelId("glm-5.1");
```

## API 速查

### ModelConfigEntry

| 字段 | 类型 | 说明 |
|------|------|------|
| `modelId` | `String` | 唯一标识，如 `"deepseek-v4"` |
| `isDefault` | `boolean` | 是否为默认模型，默认 `false` |
| `modelConfig` | `ModelRequestConfig` | 请求级配置（modelName, temperature, topP, maxTokens...） |
| `modelClient` | `ModelClientConfig` | 连接级配置（clientProvider, apiKey, apiBase, timeout...） |

### ResourceMgr 模型 API

| 方法 | 说明 |
|------|------|
| `addModel(modelId, supplier, tag)` | 注册模型 |
| `updateModel(modelId, supplier, tag)` | 更新模型（覆盖） |
| `removeModel(modelId, tag, strategy, skipMissing)` | 删除模型（至少保留一个） |
| `removeModelForce(modelId, isForce)` | 强制删除（测试清理用） |
| `getModel(modelId)` | 获取模型 |
| `resolveModel(dynamicId, clientCfg, requestCfg)` | 统一模型解析 |
| `listModelIds()` | 列出所有模型 ID |
| `setDefaultModelId(modelId)` | 设置默认模型 |
| `getDefaultModelId()` | 获取默认模型 ID |

### AgentCallbackContext

| 方法 | 说明 |
|------|------|
| `getDynamicModelId()` | 获取当前请求的动态模型 ID |
| `setDynamicModelId(id)` | 设置动态模型 ID |

## 常见问题

### 1. 不指定 model_id 会怎样？

使用默认模型（`modelConfigs` 中 `isDefault=true` 的条目）。`query` 可以是纯字符串或 Map。

### 2. 指定不存在的 model_id 会怎样？

`resolveModel` 会降级到 fallback config（调用方传入的配置），再降级到默认模型。不会抛异常。

### 3. `model_id` 应该放在哪里？

`model_id` 支持两种传递方式，均可用（详见"2. 动态选择模型"章节）：

- **方式一（推荐）**：放在 `invoke` 输入的顶层 — `Map.of("query", "...", "model_id", "deepseek-v4")`，框架透传到 `ctx.getExtra()`，Rail 从 `extra` 提取
- **方式二**：嵌套在 `query` 对象中 — `Map.of("query", Map.of("text", "...", "model_id", "deepseek-v4"))`，Rail 从 `queryPayload` 提取

### 4. 多个 Rail 都设置了 dynamicModelId 怎么办？

`beforeModelCall` 的设置会覆盖 `beforeInvoke` 的设置（时序更晚者胜出）。同钩子内多个 Rail 按 `priority()` 降序执行，后执行的覆盖先执行的。

### 5. 只配了 model + backend，不配 modelConfigs 可以吗？

可以。框架会自动将 `model` + `backend` 合并为一个 `ModelConfigEntry` 并设为默认。向后完全兼容。

### 6. 多个 DeepAgent 实例会互相影响默认模型吗？

不会。DeepAgent 构造时只在**全局默认尚未设置**时才写入 `setDefaultModelId`。如果全局默认已存在，新构造的 DeepAgent 会跳过覆盖，仅设置自身 `config.model` / `config.backend`。因此：

- 先构造的 DeepAgent 的默认模型成为全局默认
- 后构造的 DeepAgent 不会覆盖它，但其 `modelConfigs` 中标记为 `isDefault` 的模型仍可在该实例内通过 `model_id` 显式使用

### 7. 如何动态添加新模型？

```java
Supplier<Model> supplier = () -> new Model(clientConfig, requestConfig);
Runner.resourceMgr().addModel("new-model", supplier, Tag.GLOBAL);
```

添加后立即可用，下一个请求即可通过 `model_id="new-model"` 使用。
