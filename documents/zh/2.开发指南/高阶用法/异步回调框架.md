# 异步回调框架

异步回调框架（Async Callback Framework）是 openJiuwen 中面向 asyncio 的生产级事件驱动框架，用于在 Runner 或业务中注册事件回调、按优先级执行、做限流/熔断/校验等过滤、以及链式执行与回滚。Runner 内置了该框架，可通过 `Runner.callbackFramework()` 访问。

**API 文档**：完整类与方法说明见相关 API 文档。

---

## 概述

### 核心特性

- **异步优先**：基于虚拟线程执行器，支持高并发。
- **优先级控制**：数字越大越先执行，便于安排关键步骤与辅助步骤。
- **过滤系统**：全局 / 事件 / 回调三级过滤器，8 种内置过滤器，支持自定义。
- **回调链与回滚**：多步顺序执行，上一步结果传给下一步；任一步失败可触发已执行步骤的回滚。
- **多种触发模式**：顺序、并行、条件、超时、延迟、流式、生成器聚合共 7 种。
- **性能监控**：调用次数、耗时、错误率等指标，慢回调排查。
- **生命周期钩子**：BEFORE（执行前）、AFTER（执行后）、ERROR（出错时）、CLEANUP（清理时）。

### 模块结构

框架代码位于 `com.openjiuwen.core.runner.callback/`：

- `CallbackFramework.java`：核心类
- `EventFilter.java`：过滤器基类
- `CallbackChain.java`：回调链与回滚
- `CallbackMetrics.java`：指标类

## 快速开始

通过 Runner 使用回调框架：

```java
import com.openjiuwen.core.runner.Runner;
import com.openjiuwen.core.runner.callback.CallbackFramework;
import java.util.List;
import java.util.Map;

CallbackFramework framework = Runner.callbackFramework();

// 注册回调
framework.register(
        "user_login",
        kwargs -> "welcome_" + kwargs.get("username"),
        10,
        false,
        "default",
        null,
        null,
        null,
        null,
        0,
        0.0,
        null,
        "send_welcome"
);

// 触发事件
List<Object> results = framework.trigger(
        "user_login",
        new Object[0],
        Map.of("username", "alice")
);

System.out.println(results);  // ['welcome_alice']
```

不依赖 Runner 时，可单独创建框架实例：

```java
import com.openjiuwen.core.runner.callback.CallbackFramework;

CallbackFramework framework = new CallbackFramework(true);
framework.register(
        "my_event",
        kwargs -> kwargs.get("x") * 2,
        5,
        false,
        "default",
        null,
        null,
        null,
        null,
        0,
        0.0,
        null,
        "double_x"
);

List<Object> results = framework.trigger("my_event", new Object[]{3}, Map.of());
// [6]
```

## 核心概念

### 事件与回调

- **事件**：字符串标识（如 `"user_login"`、`"order.created"`），用于绑定一组回调。
- **回调**：`Function<Map<String, Object>, Object>` 函数，在事件触发时按优先级执行。同一事件可注册多个回调。
- **优先级**：`priority` 数字越大越先执行；未指定时默认为 0。

建议事件命名使用有意义的点分形式（如 `user.login`、`order.created`），避免 `event1`、`do_something` 等泛用名。

### 回调签名

Java 当前的回调统一签名：

```java
Function<Map<String, Object>, Object>
```

- 所有 keyword 风格参数都放在 `Map<String, Object>` 里
- 位置参数统一塞在 `_args`

### 执行流程（顺序触发）

1. 检查事件是否已注册；未注册则返回空列表。
2. 按优先级排序该事件下的回调。
3. 执行 **BEFORE** 钩子。
4. 遍历回调：若未启用则跳过；否则依次经过**全局过滤器 → 事件过滤器 → 该回调专属过滤器**。
5. 过滤器可返回：**CONTINUE**（继续）、**STOP**（停止整个事件）、**SKIP**（跳过当前回调）、**MODIFY**（用新参数继续）。
6. 执行回调，收集结果；若设置了 `once=true` 则执行后禁用该回调。
7. 若某回调抛错，执行 **ERROR** 钩子，并继续处理后续回调（不中断整次触发）。
8. 全部完成后执行 **AFTER** 钩子。

## 过滤器

### 内置过滤器一览

| 过滤器                      | 功能                                                                           | 典型用途       |
|--------------------------|------------------------------------------------------------------------------|------------|
| **RateLimitFilter**      | 在时间窗口内限制调用次数                                                                 | 防止回调执行过于频繁 |
| **CircuitBreakerFilter** | 失败次数达到阈值后熔断，超时后尝试恢复                                                          | 保护下游服务     |
| **ValidationFilter**     | 用自定义函数校验参数                                                                   | 参数合法性检查    |
| **LoggingFilter**        | 记录事件、回调名、参数                                                                  | 审计、调试      |
| **AuthFilter**           | 要求 kwargs 中 `user_role` 等于指定角色                                               | 基于角色的访问控制  |
| **ParamModifyFilter**    | 用 modifier(*args, **kwargs) 返回 (new_args, new_kwargs) 修改参数                   | 转换或增强参数    |
| **ConditionalFilter**    | 根据 condition 决定 CONTINUE 或 action_on_false | 条件执行       |

### 示例：限流与鉴权

```java
import com.openjiuwen.core.runner.Runner;
import com.openjiuwen.core.runner.callback.CallbackFramework;
import com.openjiuwen.core.runner.callback.RateLimitFilter;
import com.openjiuwen.core.runner.callback.AuthFilter;
import java.util.List;

CallbackFramework framework = Runner.callbackFramework();

// 添加事件级过滤器
framework.addFilter("api_call", new RateLimitFilter(100, 60.0));
framework.addFilter("admin_action", new AuthFilter("admin"));

// 注册回调
framework.register(
        "admin_action",
        kwargs -> "admin_ok_" + kwargs.get("user_id"),
        10,
        false,
        "default",
        null,
        null,
        null,
        null,
        0,
        0.0,
        null,
        "do_admin"
);

// 触发事件
List<Object> results = framework.trigger(
        "admin_action",
        new Object[0],
        Map.of("user_id", "u1", "user_role", "admin")
);
```

## 触发模式

| 方法                       | 说明                                           | 适用场景          |
|--------------------------|----------------------------------------------|---------------|
| **trigger**              | 按优先级顺序执行，收集所有结果                              | 默认方式，有依赖或需顺序时 |
| **triggerParallel**     | 并发执行，I/O 密集时可显著缩短总耗时                         | 多路拉取、并行请求     |
| **triggerUntil**        | 按顺序执行，直到某回调返回值使 condition(result) 为 True 即返回 | 降级、首选/备选      |
| **triggerChain**        | 链式执行，上一步结果传下一步，支持回滚                          | 订单/支付等事务流程    |
| **triggerWithTimeout** | 在给定总时间内执行 trigger，超时返回已收集结果                  | 控制最大耗时、SLA    |
| **triggerDelayed**      | 延迟指定秒数后执行 trigger                            | 定时、延迟任务       |
| **triggerGenerator**    | 执行事件下所有回调，聚合各回调的异步生成器或普通返回值并逐项 yield         | 多源数据聚合、流式 API |

## 回调链与回滚

用 **triggerChain** 实现多步流程；任一步返回 **ChainAction.ROLLBACK** 或抛错会按**执行顺序的逆序**执行已注册的 **rollbackHandler**。

```java
import com.openjiuwen.core.runner.Runner;
import com.openjiuwen.core.runner.callback.CallbackFramework;
import com.openjiuwen.core.runner.callback.ChainAction;
import com.openjiuwen.core.runner.callback.ChainResult;
import java.util.List;
import java.util.Map;

CallbackFramework framework = Runner.callbackFramework();

// 定义回滚处理器
Function<Map<String, Object>, Object> rollbackPayment = ctx -> {
    System.out.println("Rollback payment");
    return null;
};

Function<Map<String, Object>, Object> rollbackInventory = ctx -> {
    System.out.println("Rollback inventory");
    return null;
};

// 注册回调（带回滚处理器）
framework.register(
        "order_create",
        kwargs -> {
            Map<String, Object> order = (Map<String, Object>) kwargs.get("_last_result");
            order.put("paid", true);
            return new ChainResult(ChainAction.CONTINUE, order, null);
        },
        30,
        false,
        "default",
        null,
        null,
        null,
        rollbackPayment,
        0,
        0.0,
        null,
        "pay"
);

framework.register(
        "order_create",
        kwargs -> {
            Map<String, Object> order = (Map<String, Object>) kwargs.get("_last_result");
            int quantity = (Integer) order.getOrDefault("quantity", 0);
            if (quantity > 100) {
                return new ChainResult(ChainAction.ROLLBACK, null, new Exception("Insufficient stock"));
            }
            order.put("reserved", true);
            return new ChainResult(ChainAction.CONTINUE, order, null);
        },
        20,
        false,
        "default",
        null,
        null,
        null,
        rollbackInventory,
        0,
        0.0,
        null,
        "reserve"
);

// 执行链
ChainResult result = framework.triggerChain(
        "order_create",
        new Object[0],
        Map.of("order", Map.of("quantity", 150)),
        null
);

if (result.getAction() == ChainAction.ROLLBACK) {
    System.out.println("Order failed, rolled back");
}
```

**ChainAction**：CONTINUE（继续下一回调）、BREAK（中断链并返回当前结果）、RETRY（重试当前回调）、ROLLBACK（回滚）。

## 生命周期钩子

`HookType` 定义了四种枚举值：

- `BEFORE`
- `AFTER`
- `ERROR`
- `CLEANUP`

```java
import com.openjiuwen.core.runner.callback.HookType;
import java.util.function.Consumer;

// 注册钩子
framework.addHook("user_login", HookType.BEFORE, (context) -> {
    System.out.println("Before user_login event");
});

framework.addHook("user_login", HookType.AFTER, (context) -> {
    System.out.println("After user_login event");
});

framework.addHook("user_login", HookType.ERROR, (context) -> {
    System.out.println("Error in user_login: " + context);
});
```

### 错误不会默认终止整个事件

某个 callback 抛错后，框架会更新 metrics、执行 `ERROR` hook、写日志。如果 `ERROR` hook 没有要求重抛，`trigger` 会继续跑后面的回调。

## 指标与性能

### 指标

`CallbackMetrics` 记录：

- `call_count`
- `avg_time`
- `min_time`
- `max_time`
- `error_count`
- `error_rate`
- `last_call_time`

```java
import com.openjiuwen.core.runner.callback.CallbackMetrics;
import java.util.Map;

// 获取指标
Map<String, CallbackMetrics> metrics = framework.getMetrics("user_login", null);

// 查看慢回调
List<String> slowCallbacks = framework.getSlowCallbacks(1.0);
System.out.println("慢回调: " + slowCallbacks);
```

### 历史

历史默认是关闭的，需要显式启用：

```java
framework.enableEventHistory(true);
```

当前实现会把事件历史保存在内存里，默认上限是 `1000` 条。

```java
List<Object> history = framework.getEventHistory("user_login");
```

## 完整示例

```java
import com.openjiuwen.core.runner.Runner;
import com.openjiuwen.core.runner.RunnerConfig;
import com.openjiuwen.core.runner.callback.CallbackFramework;
import com.openjiuwen.core.runner.callback.ChainAction;
import com.openjiuwen.core.runner.callback.ChainResult;
import com.openjiuwen.core.runner.callback.RateLimitFilter;
import com.openjiuwen.core.runner.callback.ValidationFilter;
import com.openjiuwen.core.runner.callback.HookType;
import java.util.List;
import java.util.Map;
import java.util.function.Function;

public class CallbackFrameworkExample {

    public static void main(String[] args) {
        // 配置 Runner
        RunnerConfig config = RunnerConfig.builder()
                .distributedMode(false)
                .checkpointerConfig(Map.of("type", "in_memory", "conf", Map.of()))
                .build();
        Runner.setConfig(config);
        Runner.start();

        CallbackFramework framework = Runner.callbackFramework();

        // 启用历史记录
        framework.enableEventHistory(true);

        // 注册 BEFORE 钩子
        framework.addHook("order.created", HookType.BEFORE, ctx -> {
            System.out.println("=== 开始处理 order.created 事件 ===");
        });

        // 注册回调：审计日志
        framework.register(
                "order.created",
                kwargs -> "audit:" + kwargs.get("orderId"),
                20,
                false,
                "audit",
                null,
                null,
                null,
                null,
                0,
                0.0,
                null,
                "audit_callback"
        );

        // 注册回调：发送通知（带限流）
        framework.register(
                "order.created",
                kwargs -> "notify:" + kwargs.get("orderId"),
                10,
                false,
                "notification",
                null,
                List.of(new RateLimitFilter(5, 60.0)),
                null,
                null,
                0,
                0.0,
                null,
                "notify_callback"
        );

        // 注册回调：数据校验（带校验过滤器）
        framework.register(
                "order.created",
                kwargs -> {
                    Object amount = kwargs.get("amount");
                    if (amount instanceof Integer && (Integer) amount > 0) {
                        return "validated:" + kwargs.get("orderId");
                    }
                    return null;
                },
                30,
                false,
                "validation",
                null,
                List.of(new ValidationFilter(data -> {
                    Object amount = data.get("amount");
                    return amount instanceof Integer && (Integer) amount > 0;
                })),
                null,
                null,
                0,
                0.0,
                null,
                "validate_callback"
        );

        // 注册 AFTER 钩子
        framework.addHook("order.created", HookType.AFTER, ctx -> {
            System.out.println("=== 处理完成 ===");
        });

        // 触发事件
        List<Object> results = framework.trigger(
                "order.created",
                new Object[0],
                Map.of("orderId", "A-1001", "amount", 100)
        );

        System.out.println("结果: " + results);

        // 查看指标
        Map<String, Object> metrics = framework.getMetrics("order.created", null);
        System.out.println("指标: " + metrics);

        // 清理
        Runner.stop();

        System.out.println("回调框架示例完成");
    }
}
```

输出示例：

```
=== 开始处理 order.created 事件 ===
=== 处理完成 ===
结果: [validated:A-1001, audit:A-1001, notify:A-1001]
指标: {call_count=3, avg_time=..., ...}
回调框架示例完成
```

## 最佳实践

1. **事件命名**：使用有语义的点分形式（如 `user.login`、`order.created`），避免泛用名。
2. **优先级**：关键步骤（如鉴权、校验）设高 priority，辅助步骤（如通知、统计）设低 priority。
3. **命名空间与标签**：用 `namespace`、`tags` 组织回调，便于 `unregisterNamespace`、`unregisterByTags` 批量管理。
4. **错误处理**：对易失败的回调设置 **errorHandler**，或在链中使用 **rollbackHandler** 保证一致性。
5. **监控**：定期用 `getSlowCallbacks(threshold)` 排查慢回调，必要时为回调设置 **timeout**。
