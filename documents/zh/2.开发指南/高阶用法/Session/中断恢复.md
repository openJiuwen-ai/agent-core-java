openJiuwen支持工作流单组件或者多组件同时中断恢复。中断恢复包含两种场景：

- **中断交互**：工作流组件执行过程中，需要与用户交互获取更多用户信息时，需要中断当前工作流的执行，等用户交互输入后，恢复工作流的执行；
- **异常中断**：当工作流组件在执行过程中出现异常报错，需要工作流保存现场，重新执行工作流时会从上次出现异常的组件继续执行。

# 中断交互

openJiuwen支持两种中断交互模式：单组件中断和多组件中断。这两种模式分别适用于不同复杂度的业务场景：

- 单组件中断：适用于组件独立交互场景，如单一确认操作。
- 多组件中断：适用于复杂协同场景，如多类型信息同步补全。

## 单组件中断

单个组件中断等待用户输入，用户输入无需区分组件，中断组件获取到用户输入后即可继续执行。

首先定义一个带交互的组件，组件实现了`invoke`方法，在`invoke`方法提取了用户输入的命令`cmd`，调用`Session`的`interact`接口传递问题给用户，询问用户是否要执行命令，并等待用户的回答，获取到用户回答后将用户回答作为`invoke`方法的返回内容。

```java
import com.openjiuwen.core.context.ModelContext;
import com.openjiuwen.core.session.NodeSessionApi;
import com.openjiuwen.core.workflow.WorkflowComponent;

import java.util.Map;

// 带交互的组件
public class InteractiveNode extends WorkflowComponent {
    
    @Override
    public Object invoke(Object inputs, NodeSessionApi session, ModelContext context) {
        Map<String, Object> inputMap = (Map<String, Object>) inputs;
        String cmd = (String) inputMap.get("cmd");
        
        // 向用户提问，等待用户回答
        String result = session.interact("Do you want to execute the command '" + cmd + "'?");
        
        return Map.of("confirm_result", result);
    }
}
```

构建一个工作流，工作流由开始组件、交互组件、结束组件组成，组件按顺序执行。

```java
import com.openjiuwen.core.workflow.Workflow;
import com.openjiuwen.core.workflow.WorkflowCard;
import com.openjiuwen.core.workflow.component.Start;
import com.openjiuwen.core.workflow.component.End;

WorkflowCard card = WorkflowCard.builder()
        .id("interactive_workflow")
        .name("交互工作流")
        .build();

Workflow workflow = new Workflow(card);
workflow.setStartComp("start", new Start(), Map.of("command", "${cmd}"), null);
workflow.addWorkflowComp("interactive_node", new InteractiveNode(),
        Map.of("cmd", "${start.command}"),
        null);
workflow.setEndComp("end", new End(),
        Map.of("result", "${interactive_node.confirm_result}"),
        null);
workflow.addConnection("start", "interactive_node");
workflow.addConnection("interactive_node", "end");
```

然后执行工作流，执行工作流前需要生成一个`sessionId`用于创建`Session`，执行完工作流后打印工作流的输出。

```java
import com.openjiuwen.core.session.WorkflowSessionApi;
import com.openjiuwen.core.workflow.WorkflowOutput;
import com.openjiuwen.core.workflow.WorkflowExecutionState;
import java.util.UUID;

// 生成会话id
String sessionId = UUID.randomUUID().toString().substring(0, 8);

// 用户第一次输入
WorkflowOutput output = workflow.invoke(
        Map.of("cmd", "delete all files"),
        new WorkflowSessionApi(null, sessionId, Map.of()),
        null
);

System.out.println(output);
```

运行上述代码后可看到：

```text
result=[OutputSchema(type='__interaction__', index=0, payload=InteractionOutput(id='interactive_node', value="Do you want to execute the command 'delete all files'?"))] state=INPUT_REQUIRED
```

其中`output`为工作流输出，`result`为列表，列表中每个元素为流式输出的元素；`type`为`__interaction__`代表消息类型为中断消息，`index`为`0`代表组件的第一个中断。

最后再次执行工作流，再次执行工作流前需要构造交互输入，由于只有一个中断交互组件，所以构造交互输入时不需要指定交互组件`id`。将交互输入作为工作流`invoke`方法的输入传入，再次执行工作流时使用的`Session`需要用相同的`sessionId`构造，才能保证恢复中断。执行完工作流后打印工作流的输出。

```java
import com.openjiuwen.core.session.interaction.InteractiveInput;

// 包装用户回答
InteractiveInput userInput = new InteractiveInput("Yes");

// 将用户回答传入工作流，会话id要相同
WorkflowOutput output2 = workflow.invoke(
        userInput,
        new WorkflowSessionApi(null, sessionId, Map.of()),
        null
);

System.out.println(output2.getResult());
```

运行上述代码后可看到：

```text
{output={result=Yes}}
```

## 多组件中断

多个组件同时中断等待用户输入，用户需要为每个中断组件分别准备输入，所有中断组件都获取到用户输入后，工作流即可继续执行。

首先定义第一个带交互的组件：

```java
import com.openjiuwen.core.context.ModelContext;
import com.openjiuwen.core.session.NodeSessionApi;
import com.openjiuwen.core.workflow.WorkflowComponent;

import java.util.Map;

// 第一个带交互的组件
public class InteractiveNode1 extends WorkflowComponent {
    
    @Override
    public Object invoke(Object inputs, NodeSessionApi session, ModelContext context) {
        Map<String, Object> inputMap = (Map<String, Object>) inputs;
        String cmd = (String) inputMap.get("cmd");
        
        // 向用户提问，等待用户回答
        String result = session.interact("Do you want to execute the command '" + cmd + "'?");
        
        return Map.of("confirm_result", result);
    }
}
```

接着定义第二个带交互的组件：

```java
// 第二个带交互的组件
public class InteractiveNode2 extends WorkflowComponent {
    
    @Override
    public Object invoke(Object inputs, NodeSessionApi session, ModelContext context) {
        Map<String, Object> inputMap = (Map<String, Object>) inputs;
        String cmd = (String) inputMap.get("cmd");
        
        // 向用户提问，等待用户回答
        String result = session.interact("Do you want to execute the command '" + cmd + "'?");
        
        return Map.of("confirm_result", result);
    }
}
```

构建一个工作流，工作流由开始组件、两个交互组件和结束组件组成，其中两个交互组件在工作流中并发执行。

```java
Workflow workflow = new Workflow(card);
workflow.setStartComp("start", new Start(),
        Map.of("command1", "${cmd1}", "command2", "${cmd2}"),
        null);
workflow.addWorkflowComp("interactive_node1", new InteractiveNode1(),
        Map.of("cmd", "${start.command1}"),
        null);
workflow.addWorkflowComp("interactive_node2", new InteractiveNode2(),
        Map.of("cmd", "${start.command2}"),
        null);
workflow.setEndComp("end", new End(),
        Map.of("result1", "${interactive_node1.confirm_result}", 
               "result2", "${interactive_node2.confirm_result}"),
        null);
workflow.addConnection("start", "interactive_node1");
workflow.addConnection("start", "interactive_node2");
workflow.addConnection("interactive_node1", "end");
workflow.addConnection("interactive_node2", "end");
```

指定`sessionId`执行工作流，执行完工作流后打印工作流的输出。由于有两个并发执行的交互组件，所以有两个交互输出。

```java
// 生成会话id
String sessionId = UUID.randomUUID().toString().substring(0, 8);

// 用户第一次输入
WorkflowOutput output = workflow.invoke(
        Map.of("cmd1", "delete all files", "cmd2", "kill all processes"),
        new WorkflowSessionApi(null, sessionId, Map.of()),
        null
);

System.out.println(output);
```

运行上述代码后可看到：

```text
result=[OutputSchema(type='__interaction__', index=0, payload=InteractionOutput(id='interactive_node1', value="Do you want to execute the command 'delete all files'?")), OutputSchema(type='__interaction__', index=0, payload=InteractionOutput(id='interactive_node2', value="Do you want to execute the command 'kill all processes'?"))] state=INPUT_REQUIRED
```

最后再次执行工作流，再次执行工作流前需要构造交互输入，由于有两个同时执行的交互组件，所以构造交互输入时需要指定交互组件的`id`。将交互输入作为工作流`invoke`方法的输入传入，再次执行工作流时使用的`Session`需要用相同的`sessionId`构造，才能保证中断恢复。

```java
import com.openjiuwen.core.session.stream.OutputSchema;
import com.openjiuwen.core.session.interaction.InteractionOutput;
import java.util.List;

// 获取中断组件ID
List<?> result = (List<?>) output.getResult();
OutputSchema output1 = (OutputSchema) result.get(0);
OutputSchema output2 = (OutputSchema) result.get(1);

InteractionOutput interaction1 = (InteractionOutput) output1.getPayload();
InteractionOutput interaction2 = (InteractionOutput) output2.getPayload();

String nodeId1 = interaction1.getId();
String nodeId2 = interaction2.getId();

// 包装用户回答，为不同的中断组件提供不同的回答
InteractiveInput userInput = new InteractiveInput();
userInput.update(nodeId1, "Yes");
userInput.update(nodeId2, "No");

// 将用户回答传入工作流，会话id要相同
WorkflowOutput output2 = workflow.invoke(
        userInput,
        new WorkflowSessionApi(null, sessionId, Map.of()),
        null
);

System.out.println(output2.getResult());
```

运行上述代码后可看到：

```text
{output={result1=Yes, result2=No}}
```

# 异常中断

异常中断恢复是指工作流在执行过程中遇到一些非预期的异常情况，工作流也会保存现场，重新执行工作流时会从上次出现异常的组件继续执行。

以网络连接超时异常为例，介绍中断恢复过程。可看到首次进入时抛出连接超时异常，第二次进入时正常执行。

首先定义一个正常组件：

```java
import com.openjiuwen.core.context.ModelContext;
import com.openjiuwen.core.session.NodeSessionApi;
import com.openjiuwen.core.workflow.WorkflowComponent;

// 正常的组件
public class NormalNode extends WorkflowComponent {
    
    @Override
    public Object invoke(Object inputs, NodeSessionApi session, ModelContext context) {
        System.out.println("invoke normal node");
        return Map.of();
    }
}
```

接着定义一个会抛异常的组件，该组件在第一次调用时抛出异常，第二次执行时正常返回。

```java
// 会抛异常的组件
public class AbnormalNode extends WorkflowComponent {
    private boolean firstTimeInvoke = true;
    
    @Override
    public Object invoke(Object inputs, NodeSessionApi session, ModelContext context) {
        // 模拟第一次调用时出现网络超时
        if (firstTimeInvoke) {
            firstTimeInvoke = false;
            throw new RuntimeException("connection timeout");
        }
        return Map.of();
    }
}
```

构建一个工作流，工作流由开始组件、正常组件、异常组件、结束组件组成，组件按顺序执行。

```java
Workflow workflow = new Workflow(card);
workflow.setStartComp("start", new Start(), Map.of("query", "${query}"), null);
workflow.addWorkflowComp("normal_node", new NormalNode(), Map.of(), null);
workflow.addWorkflowComp("abnormal_node", new AbnormalNode(), Map.of(), null);
workflow.setEndComp("end", new End(), Map.of("result", "${start.query}"), null);
workflow.addConnection("start", "normal_node");
workflow.addConnection("normal_node", "abnormal_node");
workflow.addConnection("abnormal_node", "end");
```

执行工作流，由于存在异常组件，所以需要捕获工作流执行的异常，并打印异常信息。

```java
// 生成会话id
String sessionId = UUID.randomUUID().toString().substring(0, 8);

// 用户第一次输入
try {
    workflow.invoke(
            Map.of("query", "hello"),
            new WorkflowSessionApi(null, sessionId, Map.of()),
            null
    );
} catch (Exception e) {
    // 输出 connection timeout
    System.out.println(e.getMessage());
}
```

运行上述代码后可看到：

```text
invoke normal node
[100005] workflow component runtime error, reason: node_id: abnormal_node, ability: invoke, error: connection timeout
```

最后再次执行工作流，再次执行工作流前需要构造交互输入，异常场景只需要构造空的交互输入就行。将交互输入作为工作流`invoke`方法的输入传入，再次执行工作流时使用的`Session`需要用相同的`sessionId`构造，才能保证中断恢复。

```java
// 用户重试，使用相同的会话id，并输入空的 InteractiveInput
InteractiveInput userInput = new InteractiveInput();
WorkflowOutput output = workflow.invoke(
        userInput,
        new WorkflowSessionApi(null, sessionId, Map.of()),
        null
);

// 这里打印出 hello
Map<String, Object> result = (Map<String, Object>) output.getResult();
Map<String, Object> outputMap = (Map<String, Object>) result.get("output");
System.out.println(outputMap.get("result"));
```

运行上述代码后可看到：

```text
hello
```

第二次执行不再打印`invoke normal node`，说明第二次执行时是从正常组件之后开始执行的。

**完整代码：**

```java
import com.openjiuwen.core.context.ModelContext;
import com.openjiuwen.core.session.NodeSessionApi;
import com.openjiuwen.core.session.WorkflowSessionApi;
import com.openjiuwen.core.session.interaction.InteractiveInput;
import com.openjiuwen.core.workflow.Workflow;
import com.openjiuwen.core.workflow.WorkflowCard;
import com.openjiuwen.core.workflow.WorkflowComponent;
import com.openjiuwen.core.workflow.WorkflowOutput;
import com.openjiuwen.core.workflow.component.Start;
import com.openjiuwen.core.workflow.component.End;

import java.util.Map;
import java.util.UUID;

public class ExceptionInterruptExample {

    // 正常的组件
    static class NormalNode extends WorkflowComponent {
        @Override
        public Object invoke(Object inputs, NodeSessionApi session, ModelContext context) {
            System.out.println("invoke normal node");
            return Map.of();
        }
    }

    // 会抛异常的组件
    static class AbnormalNode extends WorkflowComponent {
        private boolean firstTimeInvoke = true;

        @Override
        public Object invoke(Object inputs, NodeSessionApi session, ModelContext context) {
            // 模拟第一次调用时出现网络超时
            if (firstTimeInvoke) {
                firstTimeInvoke = false;
                throw new RuntimeException("connection timeout");
            }
            return Map.of();
        }
    }

    public static void main(String[] args) {
        // 构建工作流
        WorkflowCard card = WorkflowCard.builder()
                .id("exception_workflow")
                .name("异常中断工作流")
                .build();

        Workflow workflow = new Workflow(card);
        workflow.setStartComp("start", new Start(), Map.of("query", "${query}"), null);
        workflow.addWorkflowComp("normal_node", new NormalNode(), Map.of(), null);
        workflow.addWorkflowComp("abnormal_node", new AbnormalNode(), Map.of(), null);
        workflow.setEndComp("end", new End(), Map.of("result", "${start.query}"), null);
        workflow.addConnection("start", "normal_node");
        workflow.addConnection("normal_node", "abnormal_node");
        workflow.addConnection("abnormal_node", "end");

        // 生成会话id
        String sessionId = UUID.randomUUID().toString().substring(0, 8);

        // 用户第一次输入
        try {
            workflow.invoke(
                    Map.of("query", "hello"),
                    new WorkflowSessionApi(null, sessionId, Map.of()),
                    null
            );
        } catch (Exception e) {
            System.out.println(e.getMessage());
        }

        // 用户重试，使用相同的会话id
        InteractiveInput userInput = new InteractiveInput();
        WorkflowOutput output = workflow.invoke(
                userInput,
                new WorkflowSessionApi(null, sessionId, Map.of()),
                null
        );

        Map<String, Object> result = (Map<String, Object>) output.getResult();
        Map<String, Object> outputMap = (Map<String, Object>) result.get("output");
        System.out.println(outputMap.get("result"));
    }
}
```

输出结果：

```text
invoke normal node
[100005] component [abnormal_node] encountered an exception while executing ability [invoke], error detail: connection timeout
hello
```

# Checkpointer清理

工作流完成后，需要显式释放Checkpointer资源：

```java
import com.openjiuwen.core.session.checkpointer.Checkpointer;
import com.openjiuwen.core.session.checkpointer.CheckpointerFactory;

Checkpointer checkpointer = CheckpointerFactory.getCheckpointer();
checkpointer.release(sessionId);
```

这一步告诉运行时："这个session相关的checkpoint已经不需要再保留了。"
