# ReActAgent 多次调用与文件工件

一个任务需要分阶段执行时，首先要决定下一阶段是继续当前对话，还是从干净上下文开始。这个选择决定是否复用 Session；是否新建 ReActAgent 并不能单独决定上下文是否延续。

## 继续同一段对话

同一个 ReActAgent 使用同一个 Session 多次调用时，第一次调用结束前会把模型上下文保存到 Session 的 `context` 状态块，后续调用再从该状态块恢复。

```java
AgentSessionApi session = AgentSession.createAgentSession("analysis-task", null, agent.getCard());

agent.invoke("收集信息并把完整结果写入 artifact.json", session);
agent.invoke("读取 artifact.json，结合刚才的讨论生成总结", session);
```

这种方式适合第二阶段需要同时利用前一阶段对话、Session 中的少量业务状态，以及工作区文件的场景。上下文仍受 ContextEngine 的窗口和压缩策略约束，不会无上限保留。

## 新建 Agent 后恢复上下文

新建 ReActAgent 不会主动查找另一个实例的内存状态。只有传入的 Session 已经包含或通过 checkpointer 恢复了 `context` 状态，新实例才能恢复此前的模型上下文。

仅创建字符串相同的 `sessionId` 不代表状态已经恢复。跨进程或重新创建 Session 时，应通过 Runner 和已配置的 checkpointer 生命周期创建、保存和恢复 Session；不要自行构造一个空 Session 并假定相同 id 会自动加载历史。

Session 中的 `context` 是 ContextEngine 使用的保留键。业务代码不应覆盖它。应用自己的状态键适合保存阶段、计数、标志和工件路径等小体量元数据：

```java
session.updateState(Map.of(
        "phase", "collected",
        "artifact_path", "artifact.json"
));
```

## 从干净上下文开始下一阶段

如果第二阶段不应继承第一阶段的对话，应使用新的 Session。两个阶段通过文件工件交接，而不是复用模型上下文：

```java
AgentSessionApi collectSession = AgentSession.createAgentSession("collect-phase", null, collector.getCard());
collector.invoke("收集信息并写入 artifact.json", collectSession);

AgentSessionApi reportSession = AgentSession.createAgentSession("report-phase", null, reporter.getCard());
reporter.invoke("读取 artifact.json 并生成报告", reportSession);
```

新建 Agent 但继续使用原 Session，仍可能恢复原上下文；新建 Session 才是上下文隔离边界。

## Session 状态和文件工件如何选择

| 数据 | 推荐位置 | 原因 |
| --- | --- | --- |
| 阶段、计数、布尔标志、工件路径 | Session 自定义状态键 | 数据小，适合随执行状态恢复 |
| 大段文本、代码、图片、批量结果 | 工作区文件 | 避免挤占 Session 状态和模型上下文 |
| 模型对话历史 | 框架管理的 `context` 状态 | 由 ContextEngine 保存、裁剪和恢复 |

Session 只保存工件路径时，不会把文件内容自动注入模型。下一阶段的指令必须明确要求读取该路径，并且 Agent 必须配置可用的文件读取工具。写入和读取还应使用同一个持久化工作区；临时目录在进程或容器结束后可能不存在。
