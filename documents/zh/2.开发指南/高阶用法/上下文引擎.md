# 上下文引擎

上下文引擎（`ContextEngine`）是 openJiuwen 中用于**模型输入上下文**构建与复用的统一组件。它是 **Agent 层面的成员**，由 Agent 在初始化时创建并持有，围绕 `Session` 和 `ModelContext` 工作，负责：

- 历史对话消息（短期记忆、窗口裁剪）
- Token 统计与窗口控制
- 多个「上下文 ID」并存的场景（例如一个会话里同时跑多条子任务）

## 核心概念

- **ContextEngine**：
  - 入口类：`com.openjiuwen.core.context.ContextEngine`。
  - 作为 **Agent 的成员**，在 Agent 初始化时创建。
  - 负责按 `sessionId + contextId` 管理多个 `ModelContext` 实例。
  - 提供统一的 `createContext`、`getContext`、`clearContext`、`saveContexts` 能力。

- **ModelContext**：
  - 代表**某个会话中的一个具体「对话上下文」**。
  - 负责维护消息列表、构造窗口（`getContextWindow()`）等。

- **ContextWindow**：
  - 表示即将送入模型的一次「上下文窗口」快照，即 `getContextWindow()` 的返回结果。
  - 封装三类内容：systemMessages（系统指令）、contextMessages（对话历史）、tools（工具定义）。

## Agent 使用上下文

ContextEngine 是 Agent 的成员，在 Agent 初始化时创建。Agent 在 `invoke` 中通过 `contextEngine` 管理上下文，典型流程如下：

### 典型调用流程

1. **Agent 初始化**：创建并持有 `contextEngine` 实例。
2. **invoke 开始**：调用 `contextEngine.createContext(session)`，建立当前会话的上下文环境。
3. **invoke 执行**：将请求委托给 Controller（如 ReActController、WorkflowController），Controller 内部按需使用 context。
4. **invoke 结束**：调用 `contextEngine.saveContexts(session)` 持久化上下文，并在适当时机 `clearContext` 释放资源。

### 代码示例：Agent 中的上下文使用

```java
import com.openjiuwen.core.context.ContextEngine;
import com.openjiuwen.core.context.ContextEngineConfig;
import com.openjiuwen.core.session.AgentSessionApi;

public class MyAgent {
    private final ContextEngine contextEngine;

    public MyAgent() {
        // ContextEngine 由基类或子类在初始化时创建
        this.contextEngine = new ContextEngine(ContextEngineConfig.builder()
                .maxContextMessageNum(200)
                .defaultWindowMessageNum(100)
                .defaultWindowRoundNum(20)
                .enableReload(true)
                .build());
    }

    public Object invoke(Map<String, Object> inputs, AgentSessionApi session) throws Exception {
        // 1. 建立上下文环境
        ModelContext context = contextEngine.createContext("planner", session);

        try {
            // 2. 委托给 Controller 执行
            Object result = controller.invoke(inputs, session, context);

            // 3. 持久化上下文
            contextEngine.saveContexts(session, null);
            return result;
        } finally {
            session.postRun();
        }
    }
}
```

**要点说明**：

- ContextEngine 由 Agent 创建并持有，不推荐在工作流组件或外部单独创建全局实例。
- `createContext`、`saveContexts` 在 Agent 的 `invoke` 入口统一调用，确保会话隔离与生命周期一致。

## Workflow 使用上下文

Workflow 执行发生在 **Agent 的 invoke 内部**，由 Controller（如 WorkflowController、LLMController）调度。Workflow 使用的 `ModelContext` 由 **Agent 的 contextEngine** 创建，并通过 `Runner.runWorkflow` 透传，而不是由 Workflow 组件自行创建。

### 典型调用流程

1. Agent 的 `invoke` 将请求委托给 Controller。
2. Controller 在需要执行 Workflow 时，通过 **Agent 的 contextEngine** 创建 ModelContext：
   - `context = contextEngine.createContext(contextId, session)`
3. 将 `context` 透传给 Workflow：
   - `Runner.runWorkflow(workflow, inputs, session, context)`
4. Runner 将 `context` 传给 `workflow.invoke(..., context)`，Workflow 内部组件即可使用该 context。

### 代码示例：Controller 中创建 context 并透传

```java
import com.openjiuwen.core.runner.Runner;
import com.openjiuwen.core.workflow.Workflow;
import com.openjiuwen.core.session.WorkflowSessionApi;

// 在 WorkflowController 的 invoke 逻辑中
public Object invoke(Map<String, Object> inputs, AgentSessionApi agentSession) throws Exception {
    Workflow workflow = getWorkflow(workflowId);
    
    // 执行 Workflow 时，通过 Agent 的 contextEngine 创建 context，并透传给 Runner
    ModelContext context = contextEngine.createContext(
            workflowId,
            agentSession
    );

    WorkflowSessionApi workflowSession = new WorkflowSessionApi(
            agentSession.getSessionId(),
            agentSession.getSessionId(),
            agentSession.getConfig()
    );

    return Runner.runWorkflow(
            workflow,
            inputs,
            workflowSession,
            context
    );
}
```

### 代码示例：Workflow 组件中接收并使用 context

```java
import com.openjiuwen.core.workflow.WorkflowComponent;
import com.openjiuwen.core.context.ModelContext;
import com.openjiuwen.core.session.NodeSessionApi;
import com.openjiuwen.core.foundation.llm.message.UserMessage;

import java.util.Map;

public class ChatNode extends WorkflowComponent {

    @Override
    public Map<String, Object> invoke(Object inputs, NodeSessionApi session, ModelContext context) {
        Map<?, ?> inputMap = (Map<?, ?>) inputs;
        String userQuery = (String) inputMap.get("query");

        // 1. context 由 Agent 透传，直接使用
        context.addMessages(java.util.List.of(new UserMessage(userQuery)));

        // 2. 构造用于调用大模型的窗口
        ContextWindow window = context.getContextWindow(
                java.util.List.of(new SystemMessage("你是一个助手")),
                null,  // tools
                20,    // maxMessages
                4      // maxRounds
        );

        java.util.List<BaseMessage> messages = window.getMessages();

        // 3. 调用 Model 完成推理（此处省略）
        // String llmResponse = model.invoke(messages);

        return Map.of("answer", "回答内容");
    }
}
```

**要点说明**：

- Workflow 使用的 context 由 Agent 的 `contextEngine.createContext` 创建，经 `Runner.runWorkflow` 透传。
- Workflow 组件的 `invoke` 签名中包含 `context: ModelContext` 参数，由框架注入，**组件不应自行调用 `contextEngine.createContext`**。

## 清理与生命周期管理

在长时间运行的服务中，需要考虑上下文的生命周期管理：

- 使用 `clearContext(sessionId)`：清理某个会话下所有上下文（例如用户主动结束会话时）。
- 使用 `clearContext(sessionId, contextId)`：只清理某个子对话。
- 在 Runner / 服务关闭前，可以选择调用 `saveContexts` + `clearContext`，将必要的信息落盘后释放内存。

示例：

```java
// 用户结束会话时
contextEngine.clearContext("s1", null);

// 仅结束某个子对话
contextEngine.clearContext("s1", "chat");
```

## ContextEngine 配置

ContextEngine 通过 `ContextEngineConfig` 进行配置：

```java
import com.openjiuwen.core.context.ContextEngineConfig;

ContextEngineConfig config = ContextEngineConfig.builder()
        .maxContextMessageNum(200)         // 最大消息数量
        .defaultWindowMessageNum(40)       // 默认窗口消息数
        .defaultWindowRoundNum(8)          // 默认窗口轮数
        .enableReload(true)                // 启用 reload
        .enableKvCacheRelease(true)        // 启用 KV cache 释放
        .build();

ContextEngine engine = new ContextEngine(config);
```

**配置参数说明**：

- `maxContextMessageNum`：上下文最大消息数量，必须大于 0
- `defaultWindowMessageNum`：默认窗口消息数
- `defaultWindowRoundNum`：默认窗口轮数
- `enableReload`：是否启用 reload 能力
- `enableKvCacheRelease`：是否启用 KV cache 释放

## 完整示例

```java
import com.openjiuwen.core.context.ContextEngine;
import com.openjiuwen.core.context.ContextEngineConfig;
import com.openjiuwen.core.context.ModelContext;
import com.openjiuwen.core.context.ContextWindow;
import com.openjiuwen.core.foundation.llm.message.UserMessage;
import com.openjiuwen.core.foundation.llm.message.SystemMessage;
import com.openjiuwen.core.foundation.llm.message.BaseMessage;
import com.openjiuwen.core.session.AgentSessionApi;

import java.util.List;
import java.util.Map;

public class ContextEngineExample {

    public static void main(String[] args) {
        // 创建 ContextEngine
        ContextEngineConfig config = ContextEngineConfig.builder()
                .maxContextMessageNum(200)
                .defaultWindowMessageNum(40)
                .defaultWindowRoundNum(8)
                .enableReload(true)
                .build();

        ContextEngine engine = new ContextEngine(config);

        // 创建 Session（示例）
        AgentSessionApi session = new AgentSessionApi("test_session", Map.of());

        // 创建上下文
        ModelContext context = engine.createContext("conversation", session);

        // 添加消息
        context.addMessages(List.of(
                new UserMessage("你好，我想问一个问题")
        ));

        // 获取上下文窗口
        ContextWindow window = context.getContextWindow(
                List.of(new SystemMessage("你是一个助手")),
                null,  // tools
                20,
                4
        );

        // 获取窗口消息
        List<BaseMessage> messages = window.getMessages();
        System.out.println("窗口消息数量: " + messages.size());

        // 保存上下文
        engine.saveContexts(session, null);

        // 清理上下文
        engine.clearContext("conversation", session.getSessionId());

        System.out.println("上下文管理示例完成");
    }
}
```

## 小结

- **ContextEngine 是 Agent 层面的成员**，由 Agent 在初始化时创建并持有。
- **Agent 使用上下文**：在 `invoke` 中调用 `createContext`、`saveContexts`，委托 Controller 执行。
- **Workflow 使用上下文**：在 Agent 的 invoke 内部，由 Controller 通过 Agent 的 `contextEngine.createContext` 创建 context，透传给 Workflow，Workflow 组件从参数接收 context，**不应自行创建**。
- 通过 `createContext`、`getContext`、`saveContexts`、`clearContext` 完成多会话隔离、多上下文 ID 管理及 Token 级别的窗口控制。
