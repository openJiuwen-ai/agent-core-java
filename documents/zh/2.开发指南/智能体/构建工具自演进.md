# Tool Optimizer（工具描述自演进）

`Tool Optimizer` 是 openJiuwen agent-core 的工具自演进模块。

它的核心目标是：
1. 给定工具描述和可调用函数；
2. 自动生成"可执行调用样本 + 指令/答案样本"；
3. 基于评估结果迭代改写描述；
4. 产出更清晰、更可执行、边界更明确的工具描述 JSON。

## 概述

该模块围绕"描述是否让模型更正确地调用工具"做优化，采用两阶段循环：
1. **Example 阶段**：生成并筛选高质量调用样本；
2. **Description 阶段**：结合正/负样本改写描述。

每轮结果会落盘，最终再经过 reviewer 做结构化、去冗余和一致性检查，输出符合原 schema 的最终描述。

## 快速开始

```java
import com.openjiuwen.agent_evolving.optimizer.tool_call.ToolOptimizerBase;
import com.openjiuwen.agent_evolving.optimizer.tool_call.utils.DefaultConfigs;
import com.openjiuwen.agent_evolving.optimizer.tool_call.utils.CustomizedPipeline;

import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class ToolOptimizerExample {
    
    public static void main(String[] args) {
        String toolName = "gaode_map_search";
        
        Map<String, Object> tool = new HashMap<>();
        tool.put("name", toolName);
        tool.put("description", "高德地图搜索工具...");
        
        Map<String, Object> configEg = DefaultConfigs.defaultConfigEg();
        Map<String, Object> configDesc = DefaultConfigs.defaultConfigDesc();
        
        configEg.put("save_dir", "./tool_optimizer_results/examples");
        configDesc.put("save_dir", "./tool_optimizer_results/descriptions");
        
        Object callableFunc = (arguments) -> {
            return searchGaodeMap((Map<String, Object>) arguments);
        };
        
        int maxTurns = 2;
        for (int turn = 0; turn < maxTurns; turn++) {
            List<Object> exampleResults = CustomizedPipeline.customizedPipeline(
                    "example", tool, configEg, callableFunc);
            
            List<Object> descResults = CustomizedPipeline.customizedPipeline(
                    "description", tool, configDesc, callableFunc);
            
            if (!descResults.isEmpty()) {
                Map<String, Object> bestDesc = extractBestDescription(descResults);
                tool.put("description", bestDesc.get("description"));
            }
        }
        
        System.out.println("Optimized tool description: " + tool.get("description"));
    }
    
    private static Object searchGaodeMap(Map<String, Object> arguments) {
        return "搜索结果...";
    }
    
    private static Map<String, Object> extractBestDescription(List<Object> results) {
        return (Map<String, Object>) results.get(0);
    }
}
```

## 输入输出协议

### 输入一：`tool`

最小必需字段：
- `name`: 工具名（字符串）
- `description`: 工具描述（推荐为 OpenAI function schema 的 JSON 字符串）

推荐 `description` 内容形态（示例）：
- 包含 `type/function/name/description/parameters/required` 等结构；
- 参数说明越准确，前几轮搜索越稳定。

### 输入二：`tool_callable`

签名约定：
- 接收 `Map<String, Object>` 作为参数
- 返回任意类型结果

注意：
- wrapper 会把生成的函数调用对象整体传入 callable（不是 kwargs 展开）；
- callable 抛异常会被记录为调用失败样本。

### 输出：`final_desc`

优化后返回的描述 JSON（Map），结构对齐原始 schema，但文本内容已经过优化。

## 运行流程

每轮（`max_turns`）执行以下步骤：

1. **Example 阶段**
- 调用 `CustomizedPipeline.customizedPipeline("example", ...)`
- 使用 `APICallToExampleMethod + BeamSearch` 生成 API call、用户指令、答案及评分；
- 结果写入 `examples/<tool_name>.json`。

2. **Description 阶段**
- 调用 `CustomizedPipeline.customizedPipeline("description", ...)`
- 使用 `ToolDescriptionMethod + BeamSearch` 基于正/负样本改写描述；
- 结果写入 `descriptions/<tool_name>.json`。

3. **后处理阶段（最终）**
- `ToolDescriptionReviewer.process(...)` 清理、交叉校验、翻译；
- `SchemaExtractor` 提取原结构模板；
- 将优化文本重新映射到 schema，得到最终输出。

## 配置

默认配置位于 `utils/DefaultConfigs.java`：
- `defaultConfigEg()`: Example 阶段
- `defaultConfigDesc()`: Description 阶段

关键参数说明：
- `gen_model_id`: 生成模型（例：`gpt-5-mini`）
- `eval_model_id`: 评估模型
- `beam_width`: 每层保留候选数
- `expand_num`: 每个节点扩展分支数
- `max_depth`: 搜索深度
- `top_k`: 返回候选路径数
- `num_workers`: 并行 worker 数
- `num_refine_steps`: Example 阶段指令迭代次数
- `num_feedback_steps`: 用于反思/改写的历史窗口
- `num_examples_for_desc`: Description 阶段读取样本数
- `score_eval_weight`: 是否叠加额外评估项（默认 0）

运行时参数：
- `max_turns`: 总迭代轮数（默认 5）
- `save_dir`: 中间结果目录（默认 `./tool_optimizer_results`）

## 核心组件

### 1) `ToolOptimizerBase`

- 优化器基类，继承自 `BaseOptimizer`
- 默认目标为 `tool_description`
- 需要子类实现 `doBackward` 和 `doStep` 方法

### 2) `CustomizedPipeline`

- 根据 `stage` 选择方法类：
  - `example` -> `APICallToExampleMethod`
  - `description` -> `ToolDescriptionMethod`
- 统一接入 `BeamSearch`
- 统一结果保存逻辑

### 3) `APICallToExampleMethod`

- 从描述生成可执行函数调用
- 调用工具获取真实输出
- 自动生成用户指令、答案与批量反思
- 输出可用于描述优化的高价值样本

### 4) `ToolDescriptionMethod`

- 读取正样本（成功）与负样本（失败）
- 先批判，再改写工具描述
- 使用 `SimpleEval` 回评估描述质量

### 5) `SimpleEval`

- 评估两部分：
  - 函数调用准确率（函数名 + 参数比对）
  - 输出有效性（LLM 打分或回退规则）
- 返回评分统计信息

### 6) `ToolDescriptionReviewer`

- 清理冗余、交叉校验原描述信息、按需翻译
- 强制回填到目标 schema
- 保证输出结构可直接用于工具定义

## 产物与中间文件

默认输出目录：`./tool_optimizer_results`

- `examples/<tool_name>.json`
  - Example 阶段每次搜索历史
- `descriptions/<tool_name>.json`
  - Description 阶段候选描述与评分
- `<tool_name>.json`（可选）
  - 外部提供的负样本文件（Description 阶段优先读取）

## 开发与扩展建议

1. **替换模型**
- 改 `configEg/configDesc` 的 `gen_model_id/eval_model_id` 即可。

2. **调整搜索开销**
- 降低 `beam_width/expand_num/max_depth/num_workers`。

3. **增强评估标准**
- 在 `SimpleEval` 中调整权重参数；
- 或扩展输出有效性评估的打分提示词。

4. **引入外部负样本**
- 将负样本放到 `save_dir/<tool_name>.json`；
- `ToolDescriptionMethod` 会优先读取。

## 运行前置条件

1. Java 环境可导入 `com.openjiuwen.agent_evolving`；
2. 可用的 OpenAI 兼容模型配置；
3. 配置文件中设置 `gen_model_id` 和 `eval_model_id`。

## 已知限制

1. `CustomizedPipeline` 中 `fn_call_path` 分支尚未实现（会抛 `UnsupportedOperationException`）；
2. 当前目录未提供自动化测试脚本，建议在接入新工具时先做小规模 smoke test；
3. 该模块依赖 LLM 贃量与稳定性，建议固定模型版本并控制随机性。
