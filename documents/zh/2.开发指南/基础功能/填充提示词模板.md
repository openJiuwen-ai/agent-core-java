# 填充提示词模板

Java 版运行时提示词装配由 `com.openjiuwen.core.foundation.prompt.PromptTemplate` 负责。它的目标不是替代高阶的 prompt builder，而是在真正发起模型调用前，把模板内容和变量装配成可直接传给 `Model`、operator 或 workflow 组件的消息列表。

## 功能定位

这里重点说明运行时模板装配：定义模板、填变量、转消息。离线提示词生成、模板优化和批量评估属于高阶用法。

## 核心类型

| 类型 | 作用 | 关键行为 |
| --- | --- | --- |
| `PromptTemplate` | 保存模板名称、内容和占位符分隔符 | `format(...)` 做变量替换，`toMessages()` 转消息列表 |
| `BaseMessage` | 消息基类 | 模板内容可以是 `List<BaseMessage>` |
| `UserMessage` / `SystemMessage` | 常见消息类型 | 用于保留角色语义，而不是把所有内容都压成单条用户消息 |

## 你需要先知道的行为

- `PromptTemplate.content` 只支持两种形态：`String` 或 `List<BaseMessage>`。
- 默认占位符分隔符是 `{{` 和 `}}`，也可以自己指定，比如 `<<name>>`。
- 模板里没用到的额外变量会被忽略。
- 模板里缺失的变量不会报错，而是保留原占位符文本。
- 如果模板内容是字符串，`toMessages()` 会把它转换成单条 `UserMessage`；如果你要显式保留 system/user 多角色，应该直接用 `List<BaseMessage>` 作为模板内容。

这些行为都能在 [`PromptTemplate.java`](../../../../src/main/java/com/openjiuwen/core/foundation/prompt/PromptTemplate.java) 和 [`PromptTemplateSystemTest.java`](../../../../src/test/java/com/openjiuwen/core/systemtest/PromptTemplateSystemTest.java) 中找到对应实现与验证。

## 接入步骤

### 1. 定义模板内容

最简单的写法是把整个 prompt 当成一个字符串模板：

```java
PromptTemplate template = PromptTemplate.builder()
        .content("你是一个精通{{domain}}的助手，请回答：{{question}}")
        .build();
```

如果你想保留消息角色，可以直接把消息列表作为模板内容：

```java
PromptTemplate template = PromptTemplate.builder()
        .content(List.of(
                new SystemMessage("你是一个精通{{domain}}的助手"),
                new UserMessage("用户问题：{{question}}")
        ))
        .build();
```

### 2. 填充变量

```java
PromptTemplate filled = template.format(Map.of(
        "domain", "Java 开发",
        "question", "如何接入 openJiuwen 的 Model？"
));
```

`format(...)` 返回的是一个新的 `PromptTemplate`，不会直接修改原模板，适合把模板作为可复用对象长期保存。

### 3. 转成消息列表

```java
List<BaseMessage> messages = filled.toMessages();
```

得到的 `messages` 就可以直接送给 `Model.invoke(...)`、`Model.stream(...)`，或者交给 workflow / operator 中需要 `List<BaseMessage>` 的地方。

## 最小示例

### 字符串模板

```java
import com.openjiuwen.core.foundation.prompt.PromptTemplate;
import com.openjiuwen.core.foundation.llm.schema.BaseMessage;
import java.util.List;
import java.util.Map;

PromptTemplate template = PromptTemplate.builder()
        .content("你好，{{name}}。请用一句话总结 {{topic}}。")
        .build();

PromptTemplate filled = template.format(Map.of(
        "name", "开发者",
        "topic", "openJiuwen Java 模型调用"
));

List<BaseMessage> messages = filled.toMessages();
System.out.println(messages.get(0).getContentAsString());
```

这条路径对应 [`PromptTemplateSystemTest.java`](../../../../src/test/java/com/openjiuwen/core/systemtest/PromptTemplateSystemTest.java) 里的基础替换测试。

### 保留多角色消息

```java
import com.openjiuwen.core.foundation.prompt.PromptTemplate;
import com.openjiuwen.core.foundation.llm.schema.BaseMessage;
import com.openjiuwen.core.foundation.llm.schema.SystemMessage;
import com.openjiuwen.core.foundation.llm.schema.UserMessage;
import java.util.List;
import java.util.Map;

PromptTemplate template = PromptTemplate.builder()
        .content(List.of(
                new SystemMessage("你是一个{{style}}的助手"),
                new UserMessage("请回答：{{question}}")
        ))
        .build();

List<BaseMessage> messages = template.format(Map.of(
        "style", "严谨",
        "question", "PromptTemplate 如何工作？"
)).toMessages();
```

这种写法的价值在于保留原始消息类型，而不是让所有模板都退化为单条 `UserMessage`。

### 自定义占位符

```java
PromptTemplate template = PromptTemplate.builder()
        .content("Hello, <<name>>!")
        .placeholderPrefix("<<")
        .placeholderSuffix(">>")
        .build();

String content = template.format(Map.of("name", "World"))
        .toMessages()
        .get(0)
        .getContentAsString();
```

这和系统测试里的自定义分隔符场景一致。

## 适合放在什么位置

`PromptTemplate` 解决的是运行时变量替换问题，最适合以下场景：

- 你已经有固定模板文本，只需要在调用前填入变量。
- 你需要把一套模板复用于多个请求，但不想手写字符串拼接。
- 你要给 workflow / operator 提供 `List<BaseMessage>` 形式的输入。

如果你关注的是离线提示词生成、批量模板管理或优化流程，那属于后面的高阶用法，不应该混到这里。

## 常见注意点

- 缺失变量不会抛错，而是保留原始占位符。这对调试友好，但也意味着你需要自己检查是否漏传关键变量。
- 如果模板内容是普通字符串，`toMessages()` 默认生成 `UserMessage`。想保留 system role，就直接把内容写成 `List<BaseMessage>`。
- Java 示例 [`ReActWeatherAgentExample.java`](../../../../examples/reac_agent/ReActWeatherAgentExample.java) 里配置的是 agent 级 `promptTemplate` 消息列表，而不是 `PromptTemplate` 对象；两者不是同一层能力。

- 离线提示词生成与优化能力单独放在高阶用法，不与运行时模板装配混写。
