# 接入大模型

`com.openjiuwen.core.foundation.llm` 提供 Java 版统一的大模型调用入口。接入时建议把配置拆成两层：

- `ModelClientConfig` 负责“怎么连到模型服务”，例如 `clientProvider`、`apiBase`、`apiKey`、超时和 SSL。
- `ModelRequestConfig` 负责“这次请求怎么调模型”，例如 `modelName`、`temperature`、`topP`、`maxTokens`。
- `Model` 负责根据 `clientProvider` 选择底层客户端，并暴露同步 `invoke(...)` 与流式 `stream(...)` 两个入口。

这里重点说明文本大模型的最小接入链路：准备配置、构造消息、调用 `Model`、读取返回值。agent 记忆、工具执行运行时和 workflow 编排请分别参考对应栏目。

## 接入前准备

开始前，你至少需要准备 4 个值：

- `clientProvider`：provider 名称，例如 `OpenAI`、`SiliconFlow`、`DashScope`。
- `apiBase`：模型服务根地址，例如 `https://api.openai.com/v1`。不要拼上 `/chat/completions`。
- `apiKey`：调用模型服务所需的鉴权令牌。
- `modelName`：本次要调用的模型名，例如 `gpt-4o-mini`、`Qwen/Qwen3-32B`。

当前 Java 仓库会在 `Model` 类加载时自动注册内置 provider 工厂，开箱即可直接使用：

- `OpenAI`
- `OpenRouter`
- `SiliconFlow`
- `DashScope`
- `InferenceAffinity`
- `inference_affinity`

只有在你要接入自定义 provider 时，才需要手动调用 `Model.registerFactory(...)` 注册自己的工厂实现。

## 两层配置

### 连接层：`ModelClientConfig`

`ModelClientConfig` 描述网络连接和客户端行为。推荐先用最小配置跑通，再按需要增加请求头、证书或超时。

```java
ModelClientConfig clientConfig = ModelClientConfig.builder()
        .clientProvider("OpenAI")
        .apiKey(System.getenv("OPENJIUWEN_API_KEY"))
        .apiBase(System.getenv("OPENJIUWEN_API_BASE"))
        .timeout(30.0)
        .verifySsl(true)
        .build();
```

| 字段 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `clientProvider` | 是 | 无 | 选择底层 provider 工厂。建议使用内置名称，如 `OpenAI`、`OpenRouter`、`SiliconFlow`、`DashScope`、`InferenceAffinity`。当前实现支持大小写兼容匹配，但仍建议按内置名称原样填写。 |
| `apiBase` | 是 | 无 | 模型服务根地址。不要带 `/chat/completions`。 |
| `apiKey` | 是 | 无 | 鉴权令牌。内置 OpenAI 兼容客户端会自动放进 `Authorization: Bearer ...`。 |
| `timeout` | 否 | `60.0` | 请求超时时间，单位秒。必须大于 `0`。 |
| `maxRetries` | 否 | `3` | 预留的重试次数配置。是否生效取决于具体 provider 实现。 |
| `verifySsl` | 否 | `true` | 是否校验证书。联调或自签证书环境才建议临时关闭。 |
| `sslCert` | 否 | `null` | 自定义证书路径，配合 `verifySsl` 使用。 |
| `headers` | 否 | 空 `Map` | 额外请求头，适合传 provider 私有 header。 |
| `clientId` | 否 | 自动生成 UUID | 客户端实例标识。大多数场景无需手动设置。 |

### 请求层：`ModelRequestConfig`

`ModelRequestConfig` 描述模型名和默认推理参数。这里配置的是“默认值”，每次调用时也可以单独覆盖。

```java
ModelRequestConfig requestConfig = ModelRequestConfig.builder()
        .modelName(System.getenv("OPENJIUWEN_MODEL_NAME"))
        .temperature(0.6)
        .topP(0.8)
        .maxTokens(256)
        .build();
```

| 字段 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `modelName` | 建议视为必填 | `""` | 默认值是空字符串，但真正发请求时应显式设置，否则通常会被服务端判为非法模型。序列化后对应请求里的 `model`。 |
| `temperature` | 否 | `0.95` | 控制随机性。值越高，输出通常越发散。 |
| `topP` | 否 | `0.1` | 控制采样范围。与 `temperature` 一样属于推理采样参数。 |
| `maxTokens` | 否 | `null` | 最大生成 token 数。 |
| `stop` | 否 | `null` | 停止序列。 |
| `user` | 否 | `null` | 透传到底层请求的用户标识。 |
| `seed` | 否 | `null` | 随机种子。是否生效取决于 provider 是否支持。 |
| `extraFields` | 否 | 空 `Map` | provider 私有扩展字段，会一并写入最终请求体。 |

### 覆盖关系

创建 `Model` 后，请求参数有两层来源：

- `ModelRequestConfig` / `ModelClientConfig` 提供默认值。
- `invoke(...)` / `stream(...)` 的入参优先级更高，会覆盖配置对象中的同名设置。

例如：

- 调用时传了 `temperature`，优先使用本次调用传入的值。
- 调用时没传 `model`，会回退到 `ModelRequestConfig.modelName`。
- 调用时传了 `timeout`，会覆盖 `ModelClientConfig.timeout`。
- 调用时传了 `kwargs`，会覆盖 `ModelRequestConfig.extraFields` 中的同名字段。

## 请求级动态 Authorization

默认情况下，内置 OpenAI 兼容客户端会使用 `ModelClientConfig.apiKey` 生成请求头：

```text
Authorization: Bearer <apiKey>
```

如果你的模型网关需要按租户、用户或会话动态切换认证信息，可以在单次调用的 `kwargs.custom_headers` 中传入完整的 `Authorization` 头值。这个值只对本次请求生效，不会修改 `ModelClientConfig`。

```java
String tenantToken = loadTenantToken();

Map<String, Object> kwargs = Map.of(
        "custom_headers", Map.of(
                "Authorization", "Bearer " + tenantToken,
                "X-Tenant-Id", "tenant-a"
        )
);

AssistantMessage response = model.invoke(
        messages,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        kwargs
);
```

也可以使用驼峰写法 `customHeaders`，适合和 Java 侧已有字段命名保持一致：

```java
Map<String, Object> kwargs = Map.of(
        "customHeaders", Map.of(
                "Authorization", "Custom tenant-token"
        )
);
```

流式调用同样支持：

```java
Iterator<AssistantMessageChunk> chunks = model.stream(
        messages,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        Map.of("custom_headers", Map.of(
                "Authorization", "Bearer " + tenantToken
        ))
);
```

使用时注意以下规则：

- `Authorization` 的 key 大小写不敏感，`Authorization`、`authorization`、`AUTHORIZATION` 都可以识别。
- `Authorization` 的 value 必须是完整头值；SDK 不会自动补 `Bearer` 前缀。例如你可以传 `Bearer xxx`，也可以传网关要求的 `Basic xxx` 或自定义 scheme。
- 如果请求级 `Authorization` 是空白字符串，会回退到 `apiKey` 生成的默认 `Authorization: Bearer <apiKey>`。
- `ModelClientConfig.customHeaders.Authorization` 仍然不会覆盖默认认证头。静态配置里的 `Authorization` 会被过滤，只有请求级 `custom_headers` / `customHeaders` 可以显式覆盖。
- 动态 `Authorization` 不会写入请求体，也不会作为普通 `extra_headers` 进入 tracer 记录，避免把敏感值落入日志或链路追踪参数。
- 包含换行符等非法控制字符的 `Authorization` 会被拒绝，避免 header 注入风险。

## 最小调用示例

下面是一段最小接入示例。对内置 provider 来说，不需要额外手动注册工厂。

```java
import com.openjiuwen.core.foundation.llm.Model;
import com.openjiuwen.core.foundation.llm.schema.AssistantMessage;
import com.openjiuwen.core.foundation.llm.schema.ModelClientConfig;
import com.openjiuwen.core.foundation.llm.schema.ModelRequestConfig;
import com.openjiuwen.core.foundation.llm.schema.SystemMessage;
import com.openjiuwen.core.foundation.llm.schema.UserMessage;

import java.util.List;

ModelClientConfig clientConfig = ModelClientConfig.builder()
        .clientProvider("OpenAI")
        .apiKey(System.getenv("OPENJIUWEN_API_KEY"))
        .apiBase(System.getenv("OPENJIUWEN_API_BASE"))
        .timeout(30.0)
        .verifySsl(true)
        .build();

ModelRequestConfig requestConfig = ModelRequestConfig.builder()
        .modelName(System.getenv("OPENJIUWEN_MODEL_NAME"))
        .temperature(0.6)
        .topP(0.8)
        .maxTokens(256)
        .build();

Model model = new Model(clientConfig, requestConfig);

List<Object> messages = List.of(
        new SystemMessage("你是一个简洁的助手。"),
        new UserMessage("请用一句话介绍 openJiuwen Java 的模型调用方式。")
);

AssistantMessage response = model.invoke(
        messages,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null
);

System.out.println(response.getContentAsString());
```

这 10 个位置参数里，只有你要覆盖默认配置时才需要传值；不覆盖时传 `null` 即可。`messages` 是唯一必须有意义的输入，`modelName` 则建议在 `ModelRequestConfig` 里提前配好。

## `invoke(...)` 非流式调用

`invoke(...)` 会一次性返回完整的 `AssistantMessage`，适合脚本、测试、批处理和不需要逐块刷新的场景。

```java
public AssistantMessage invoke(
        Object messages,
        Object tools,
        Float temperature,
        Float topP,
        String model,
        Integer maxTokens,
        String stop,
        BaseOutputParser outputParser,
        Float timeout,
        Map<String, Object> kwargs
) throws Exception
```

### 参数说明

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| `messages` | 是 | 模型输入。支持 `String`、`List<BaseMessage>`、`List<Map<String, Object>>`。如果直接传 `String`，框架会把它当成一条 `user` 消息。消息列表为空会直接报错。 |
| `tools` | 否 | 工具定义。支持 `List<ToolInfo>` 或 `List<Map<String, Object>>`。传入后框架会把工具转成 OpenAI 函数调用格式，并自动带上 `tool_choice=auto`。 |
| `temperature` | 否 | 覆盖 `ModelRequestConfig.temperature`。 |
| `topP` | 否 | 覆盖 `ModelRequestConfig.topP`。 |
| `model` | 否 | 覆盖 `ModelRequestConfig.modelName`。 |
| `maxTokens` | 否 | 覆盖 `ModelRequestConfig.maxTokens`。 |
| `stop` | 否 | 覆盖 `ModelRequestConfig.stop`。 |
| `outputParser` | 否 | 输出解析器。若解析成功，结果会写进返回对象的 `parserContent`。 |
| `timeout` | 否 | 覆盖 `ModelClientConfig.timeout`，单位秒。 |
| `kwargs` | 否 | 额外请求参数，会透传到底层请求体，并覆盖 `extraFields` 中同名键。适合传 provider 私有参数。 |

推荐的消息写法是显式构造消息对象列表：

```java
List<Object> messages = List.of(
        new SystemMessage("你是一个简洁的助手。"),
        new UserMessage("你好")
);
```

如果你只是想快速发起一条单轮请求，也可以直接传字符串：

```java
AssistantMessage response = model.invoke(
        "你好",
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null
);
```

### 返回值说明

`invoke(...)` 返回 `AssistantMessage`。最常用字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `content` | `Object` | 模型主回复内容。纯文本场景通常可直接用 `getContentAsString()` 读取。 |
| `toolCalls` | `List<ToolCall>` | 模型要求调用的工具列表。函数调用场景下重点看这里。 |
| `usageMetadata` | `UsageMetadata` | 用量统计，常见字段包括 `modelName`、`inputTokens`、`outputTokens`、`totalTokens`、`cacheTokens`。 |
| `finishReason` | `String` | 结束原因。常见值包括 `stop`、`tool_calls`。 |
| `reasoningContent` | `String` | 模型返回的推理内容。是否存在取决于 provider 和模型。 |
| `parserContent` | `Object` | `outputParser` 解析后的结构化结果。解析失败时通常为 `null`。 |

典型读取方式如下：

```java
AssistantMessage response = model.invoke(
        messages, null, null, null, null, null, null, null, null, null
);

System.out.println(response.getContentAsString());

if (response.getUsageMetadata() != null) {
    System.out.println(response.getUsageMetadata().getTotalTokens());
}

if (response.getToolCalls() != null && !response.getToolCalls().isEmpty()) {
    System.out.println(response.getToolCalls().get(0).getName());
}
```

## `stream(...)` 流式调用

`stream(...)` 返回同步 `Iterator<AssistantMessageChunk>`，适合边生成边展示的场景。它不是 Python 那种 `async for` 风格，也不是异步返回值。

```java
public Iterator<AssistantMessageChunk> stream(
        Object messages,
        Object tools,
        Float temperature,
        Float topP,
        String model,
        Integer maxTokens,
        String stop,
        BaseOutputParser outputParser,
        Float timeout,
        Map<String, Object> kwargs
) throws Exception
```

### 参数说明

`stream(...)` 的参数与 `invoke(...)` 完全一致，覆盖关系也一致。

### 返回值说明

`stream(...)` 返回 `Iterator<AssistantMessageChunk>`。每次 `next()` 得到一个分块对象，常见字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `content` | `Object` | 当前分块的文本增量。纯文本场景通常可用 `getContentAsString()` 直接打印。 |
| `toolCalls` | `List<ToolCall>` | 当前分块里的工具调用增量。工具调用流式场景下，单个 chunk 可能只包含参数片段。 |
| `usageMetadata` | `UsageMetadata` | 用量统计，通常只会出现在末尾 chunk。 |
| `finishReason` | `String` | 当前分块的完成状态。中间过程常见值是 `"null"`，结束时才会变成 `stop`、`tool_calls` 等。 |
| `reasoningContent` | `String` | 当前分块的推理内容增量。 |
| `parserContent` | `Object` | 流式解析器在当前时刻成功解析出的结构化结果。 |

最常见的消费方式是逐块打印文本：

```java
Iterator<AssistantMessageChunk> chunks = model.stream(
        messages,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null
);

StringBuilder fullText = new StringBuilder();
while (chunks.hasNext()) {
    AssistantMessageChunk chunk = chunks.next();
    String delta = chunk.getContentAsString();
    if (delta != null && !delta.isEmpty()) {
        System.out.print(delta);
        fullText.append(delta);
    }
}
```

如果你在做工具调用流式消费，建议把 chunk 累积后再读取完整的 `toolCalls`：

```java
AssistantMessageChunk merged = null;
while (chunks.hasNext()) {
    AssistantMessageChunk chunk = chunks.next();
    merged = merged == null ? chunk : merged.merge(chunk);
}

if (merged != null && merged.getToolCalls() != null) {
    System.out.println(merged.getToolCalls().get(0).getArguments());
}
```

## 工具调用最小说明

如果你只需要把工具定义暴露给模型，而不是让 agent 真正执行工具，可以直接把 `List<ToolInfo>` 传给 `Model.invoke(...)` 或 `Model.stream(...)`。

```java
import com.openjiuwen.core.foundation.tool.schema.ToolInfo;

List<ToolInfo> tools = List.of(
        ToolInfo.builder()
                .name("get_weather")
                .description("根据城市查询天气")
                .parameters(Map.of(
                        "type", "object",
                        "properties", Map.of(
                                "city", Map.of("type", "string", "description", "城市名")
                        ),
                        "required", List.of("city")
                ))
                .build()
);
```

工具本体如何定义、包装和注册，见 [自定义工具](自定义工具.md)。

## 常见坑和排查

- `messages` 不能为空。空列表或 `null` 会在请求发出前直接报错。
- `modelName` 默认值是空字符串，不是真正可用的默认模型。接文本模型时应显式配置。
- `apiBase` 只填服务根地址，不要拼上 `/chat/completions`。
- `clientProvider` 写错时，`Model` 构造阶段就会报 provider 不可用；自定义 provider 还要先 `registerFactory(...)`。
- `timeout` 必须大于 `0`，否则 `ModelClientConfig.builder().build()` 会直接抛异常。
- Java 版 `invoke(...)` / `stream(...)` 是同步接口，不要照着 Python 文档写 `await` 或 `async for`。
- `LlmConnectionExample.java` 里演示了手动注册 `SimpleOpenAiFactory`，那是为了展示自定义 OpenAI 兼容 provider。使用内置 provider 时不需要照抄这一步。
- 如果只是想让模型“知道有这个工具”，传 `ToolInfo` 即可；如果要让 agent 真的执行工具，还需要把工具对象注册进运行时。

## 使用边界

- 这里聚焦 Java 文本模型接入，不展开图片、语音、视频生成接口。
- 文中的示例和字段说明均以当前 Java 仓库源码、API 文档与测试示例为准。
- 阅读重点放在四件事：怎么接通、传什么、返回什么、出错先查什么。
