# 接入大模型

`com.openjiuwen.core.foundation.llm` 提供 Java 版统一的大模型调用入口。推荐把“怎么连到模型服务”和“这次请求想怎么调模型”拆成两层配置：

- `ModelClientConfig` 负责连接层配置，例如 `clientProvider`、`apiBase`、`apiKey`、超时和 SSL。
- `ModelRequestConfig` 负责请求层配置，例如 `modelName`、`temperature`、`topP`、`maxTokens`。
- `Model` 根据 `clientProvider` 选择已注册的 provider 工厂，并把同步调用或流式调用转发给底层客户端。

## 功能定位

本页只覆盖最小模型接入链路：准备连接配置、准备请求配置、构造消息、调用 `Model`。agent 记忆、工具注册和 workflow 编排不在本页展开。

## 核心类型

| 类型 | 作用 | 典型用法 |
| --- | --- | --- |
| `ModelClientConfig` | 描述模型服务连接方式 | 配 `clientProvider`、`apiBase`、`apiKey`、`timeout`、`verifySsl` |
| `ModelRequestConfig` | 描述单次请求的模型参数 | 配 `modelName`、`temperature`、`topP`、`maxTokens` |
| `Model` | 统一调用入口 | 用 `invoke(...)` 获取完整结果，用 `stream(...)` 获取分块结果 |
| `SystemMessage` / `UserMessage` | 构造消息输入 | 推荐按对话顺序组成 `List<?> messages` |

## 接入步骤

### 1. 准备连接配置

先把 provider、地址、密钥和网络参数放进 `ModelClientConfig`。如果你没有显式设置 `clientId`，builder 会自动生成一个 UUID，因此大多数场景只需要关注连接本身。

```java
ModelClientConfig clientConfig = ModelClientConfig.builder()
        .clientProvider("OpenAI")
        .apiKey(System.getenv("OPENJIUWEN_API_KEY"))
        .apiBase(System.getenv("OPENJIUWEN_API_BASE"))
        .timeout(30.0)
        .verifySsl(true)
        .build();
```

`clientProvider` 是 Java 版选底层客户端的关键字段，`Model` 会按它查找已注册工厂。

### 2. 准备请求配置

把模型名和本次推理参数放进 `ModelRequestConfig`。Java 版字段名是 `modelName`，序列化时才映射到请求里的 `model` 字段。

```java
ModelRequestConfig requestConfig = ModelRequestConfig.builder()
        .modelName(System.getenv("OPENJIUWEN_MODEL_NAME"))
        .temperature(0.6)
        .topP(0.8)
        .maxTokens(256)
        .build();
```

### 3. 创建 `Model`

```java
Model model = new Model(clientConfig, requestConfig);
```

如果 `clientProvider` 不存在、连接配置为空，或者 provider 没有对应工厂，构造阶段就会直接失败，这比等到第一次调用时再报错更容易排查。

### 4. 准备消息输入

Java 版最稳妥的写法是显式传入消息对象列表：

```java
List<Object> messages = List.of(
        new SystemMessage("你是一个简洁的助手。"),
        new UserMessage("请用一句话介绍 openJiuwen Java 的模型调用方式。")
);
```

如果你后面要做函数调用，也可以在这一层把 `List<ToolInfo>` 作为 `tools` 参数一起传给 `Model.invoke(...)`。工具如何定义与注册，见 [自定义工具](自定义工具.md)。

### 5. 发起调用

#### 非流式调用

`invoke(...)` 会一次性返回完整 `AssistantMessage`，适合脚本、测试和不需要逐块刷新的场景。

```java
AssistantMessage response = model.invoke(
        messages,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null
);

System.out.println(response.getContentAsString());
```

这条调用链可以直接对照 [`LlmConnectionExample.java`](../../../../src/test/java/com/openjiuwen/core/foundation/llm/LlmConnectionExample.java)；该示例还演示了如何读取 `usageMetadata`。

#### 流式调用

Java 当前的流式调用返回同步 `Iterator<AssistantMessageChunk>`：

```java
Iterator<AssistantMessageChunk> chunks = model.stream(
        messages,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null,
        null
);

while (chunks.hasNext()) {
    AssistantMessageChunk chunk = chunks.next();
    String delta = chunk.getContentAsString();
    if (delta != null && !delta.isEmpty()) {
        System.out.print(delta);
    }
}
```

这也是 [`LlmConnectionExample.java`](../../../../src/test/java/com/openjiuwen/core/foundation/llm/LlmConnectionExample.java) 里的实际写法。

## 最小示例

下面是一段可以直接映射到当前仓库 API 的最小模型调用代码：

```java
import com.openjiuwen.core.foundation.llm.Model;
import com.openjiuwen.core.foundation.llm.schema.AssistantMessage;
import com.openjiuwen.core.foundation.llm.schema.ModelClientConfig;
import com.openjiuwen.core.foundation.llm.schema.ModelRequestConfig;
import com.openjiuwen.core.foundation.llm.schema.SystemMessage;
import com.openjiuwen.core.foundation.llm.schema.UserMessage;
import java.util.List;

ModelClientConfig clientConfig = ModelClientConfig.builder()
        .clientProvider("OpenAI")
        .apiKey(System.getenv("OPENJIUWEN_API_KEY"))
        .apiBase(System.getenv("OPENJIUWEN_API_BASE"))
        .timeout(30.0)
        .verifySsl(true)
        .build();

ModelRequestConfig requestConfig = ModelRequestConfig.builder()
        .modelName(System.getenv("OPENJIUWEN_MODEL_NAME"))
        .temperature(0.6)
        .topP(0.8)
        .maxTokens(256)
        .build();

Model model = new Model(clientConfig, requestConfig);
List<Object> messages = List.of(
        new SystemMessage("你是一个简洁的助手。"),
        new UserMessage("你好")
);

AssistantMessage response = model.invoke(
        messages, null, null, null, null, null, null, null, null, null
);
System.out.println(response.getContentAsString());
```

如果你想看一个更接近真实应用的例子，可以继续阅读 [`examples/reac_agent/ReActWeatherAgentExample.java`](../../../../examples/reac_agent/ReActWeatherAgentExample.java)。这个例子不是直接调用 `Model`，而是通过 `ReActAgentConfig.configureModelClient(...)` 把相同的底层模型配置挂到 agent 上。

## 常见注意点

- 请求配置字段使用 `modelName`，序列化时才映射到底层请求字段。
- `Model.invoke(...)` 和 `Model.stream(...)` 都是同步调用入口。
- `Model` 负责选择底层 provider 客户端，但不会替你管理工具注册、agent 记忆或 workflow 编排；这些能力属于后续栏目。
- 连通性排查优先看 `LlmConnectionExample`：它覆盖了配置、非流式调用、流式调用三条最短路径。
