# 自定义工具

Java 版工具体系位于 `com.openjiuwen.core.foundation.tool`。它负责把本地函数、HTTP 接口和 MCP 服务统一描述成模型可识别的工具，再把这些工具暴露给 `Model`、agent 或 workflow。

## 功能定位

本页聚焦工具契约定义和运行时接入：如何描述工具输入、如何包装本地或远端能力、以及如何把工具暴露给模型或 agent。

## 核心类型

| 类型 | 作用 | 典型场景 |
| --- | --- | --- |
| `Tool` | 所有工具的抽象基类 | 上层统一调用契约 |
| `ToolCard` | 工具元数据与输入 Schema | 本地函数、模型函数调用描述 |
| `LocalFunction` | 把 `Function<Map<String, Object>, Object>` 包装为工具 | 本地逻辑、轻量适配器 |
| `@ToolDefinition` + `AnnotatedToolFactory` | 从注解方法批量生成 `LocalFunction` | 现有业务方法想快速暴露为工具 |
| `RestfulApi` + `RestfulApiCard` | 把 HTTP 接口包装为工具 | 调天气、搜索、企业内部 API |
| `McpTool` + `McpToolCard` | 把远端 MCP 工具包装为本地工具 | 接入已有 MCP server |

## 接入步骤

无论走哪一种实现方式，主线都一样：

1. 先定义工具的名字、描述和输入 Schema。
2. 再选择一种运行时实现方式：本地函数、REST 或 MCP。
3. 最后把工具暴露给模型调用或 agent 能力管理。

Java 版本地工具的两个主入口是：

- 显式创建 `ToolCard`，再用 `LocalFunction` 包装；
- 或使用 `@ToolDefinition`，再由 `AnnotatedToolFactory.scan(...)` 扫描成工具列表。

## 最小示例：用 `ToolCard + LocalFunction` 包装本地函数

这是最直接、最容易验证的一种方式。`LocalFunction` 会在执行前按 `ToolCard.inputParams` 对输入做校验和格式化。

```java
import com.openjiuwen.core.foundation.tool.ToolCard;
import com.openjiuwen.core.foundation.tool.function.LocalFunction;
import java.util.List;
import java.util.Map;

ToolCard card = ToolCard.builder()
        .id("weather_tool")
        .name("get_weather")
        .description("根据城市查询天气")
        .inputParams(Map.of(
                "type", "object",
                "properties", Map.of(
                        "city", Map.of("type", "string", "description", "城市名")
                ),
                "required", List.of("city")
        ))
        .build();

LocalFunction tool = new LocalFunction(card, inputs -> Map.of(
        "city", inputs.get("city"),
        "temperature", 22,
        "condition", "sunny"
));

Object result = tool.invoke(Map.of("city", "北京"));
System.out.println(result);
```

这一写法可以直接对应 [`ToolSystemTest.java`](../../../../src/test/java/com/openjiuwen/core/systemtest/ToolSystemTest.java)。

### 什么时候用它

- 你手里已经有本地 Java 逻辑，只缺一个模型可调用的包装层。
- 你想精确控制输入 Schema，而不依赖反射扫描。
- 你需要在单元测试或系统测试里快速构造一个可调用工具。

## 其他实现方式

### 用 `@ToolDefinition` 扫描已有方法

如果你已经有现成的方法集合，不想手写每个 `ToolCard`，可以用 `@ToolDefinition` 标注方法，再交给 `AnnotatedToolFactory` 扫描。

```java
import com.openjiuwen.core.foundation.tool.annotation.ToolDefinition;
import com.openjiuwen.core.foundation.tool.function.AnnotatedToolFactory;
import com.openjiuwen.core.foundation.tool.function.LocalFunction;
import java.util.List;

final class WeatherTools {

    @ToolDefinition(name = "get_weather", description = "根据城市查询天气")
    String getWeather(String city) {
        return city + " 晴，22℃";
    }
}

WeatherTools target = new WeatherTools();
List<LocalFunction> tools = AnnotatedToolFactory.scan(target);
```

`@ToolDefinition` 配合 `AnnotatedToolFactory.scan(...)` 会按方法签名和注解内容生成 `ToolCard`，并把方法包装成 `LocalFunction`。

### 用 `RestfulApi` 包装 HTTP 接口

`RestfulApi` 适合把真实在线服务接进 agent。当前仓库里的 [`ReActWeatherAgentExample.java`](../../../../examples/reac_agent/ReActWeatherAgentExample.java) 就使用了这条路径。

```java
import com.openjiuwen.core.foundation.tool.Tool;
import com.openjiuwen.core.foundation.tool.service_api.RestfulApi;
import com.openjiuwen.core.foundation.tool.service_api.RestfulApiCard;
import java.util.Map;

RestfulApiCard card = RestfulApiCard.builder()
        .id("weather_tool")
        .name("WeatherReporter")
        .description("根据 city 查询实时天气和预报")
        .url("https://uapis.cn/api/v1/misc/weather")
        .method("GET")
        .timeout(10.0)
        .queries(Map.of("lang", "zh", "forecast", true))
        .inputParams(Map.of(
                "type", "object",
                "properties", Map.of(
                        "city", Map.of(
                                "type", "string",
                                "description", "城市名称",
                                "location", "query"
                        )
                )
        ))
        .build();

Tool tool = new RestfulApi(card);
```

几个需要记住的行为：

- `RestfulApiCard` 默认方法是 `POST`，默认超时是 `60` 秒。
- 当前只支持 `GET` 和 `POST`。
- `GET` 请求会把 body 参数并入查询串；非 `GET` 请求会统一序列化为 JSON 请求体。
- 返回结果会被标准化成包含 `code`、`data`、`url`、`headers`、`reason`、`message` 的结果 `Map`。

这些行为都能在 [`RestfulApi.md`](../API文档/com.openjiuwen.core/foundation/tool/service_api/RestfulApi.md) 和 [`ToolAdvancedSystemTest.java`](../../../../src/test/java/com/openjiuwen/core/systemtest/ToolAdvancedSystemTest.java) 里找到依据。

### 用 `McpTool` 包装 MCP 服务

如果你的工具已经通过 MCP server 暴露出来，Java 版可以直接用 `McpTool` 包装。它会调用 `McpClient.callTool(...)` 并返回 `Map.of("result", result)`。

```java
import com.openjiuwen.core.foundation.tool.mcp.McpClient;
import com.openjiuwen.core.foundation.tool.mcp.McpTool;
import com.openjiuwen.core.foundation.tool.mcp.McpToolCard;

McpToolCard card = McpToolCard.builder()
        .id("mcp_search")
        .name("search")
        .description("通过 MCP 执行搜索")
        .serverName("search-server")
        .serverId("srv-search")
        .build();

McpClient client = ...;
McpTool tool = new McpTool(client, card);
```

需要注意：

- `McpTool.stream(...)` 不支持流式调用，会直接抛错。
- MCP 更适合复用已有远端工具，而不是替代本地 `LocalFunction`。

## 把工具暴露给模型或 Agent

### 直接给 `Model` 用

如果你只需要函数调用定义，不需要完整 agent 运行时，可以把 `ToolInfo` 列表直接传给 `Model.invoke(...)`：

```java
List<ToolInfo> tools = List.of(card.toolInfo());
AssistantMessage response = model.invoke(
        messages,
        tools,
        0.1f,
        null,
        null,
        128,
        null,
        null,
        20.0f,
        null
);
```

这条调用路径可以对照 [`LLMToolCallingSystemTest.java`](../../../../src/test/java/com/openjiuwen/core/systemtest/LLMToolCallingSystemTest.java)。

### 注册到 `ReActAgent`

如果你要让 agent 真正执行工具，还需要把工具注册进资源管理器，并把工具卡片加入 `AbilityManager`。当前仓库的天气示例就是这样做的：

```java
Runner.resourceMgr().addTool(tool, AGENT_ID);
agent.getAbilityManager().add(tool.getCard());
```

完整写法见 [`ReActWeatherAgentExample.java`](../../../../examples/reac_agent/ReActWeatherAgentExample.java)。

## 常见注意点

- Java 版本地工具主入口是 `ToolCard + LocalFunction` 或 `@ToolDefinition`。
- `LocalFunction.stream(...)` 只有在底层函数返回 `Iterator` 或 `Iterable` 时才成立；否则会报错。
- `RestfulApi` 构造阶段就会校验 URL scheme 和 HTTP method，非法配置不会拖到运行时才爆。
- 如果你只是想让模型“知道有这个工具”，传 `ToolInfo` 即可；如果你要让 agent 真正执行工具，还必须把工具对象注册到运行时。
