# 使用预置组件

Python 版文档把预置组件写成一篇长教程：先讲 `Start` / `End`，再讲模型、提问器、意图识别、分支、记忆、知识检索、工具、子工作流和循环。Java 版也应按这个学习顺序组织，只是示例必须换成 Java 0.1.14 当前真实 API。

本页聚焦这些公开入口：

- `com.openjiuwen.core.workflow.component`
- `com.openjiuwen.core.workflow.component.llm`
- `com.openjiuwen.core.workflow.component.resource`
- `com.openjiuwen.core.workflow.component.tool`
- `com.openjiuwen.core.workflow.component.loop`
- `com.openjiuwen.core.workflow.components.*` 兼容包装包

如果你只是想先理解组件输入输出和能力类型，可先读 [使用组件](README.md)、[定义组件输入输出格式](定义组件输入输出格式.md) 和 [组件支持的能力类型](组件支持的能力类型.md)。

## Python 到 Java 的基本映射

| Python 文档写法 | Java 0.1.14 写法 | 说明 |
| --- | --- | --- |
| `workflow.set_start_comp(...)` | `workflow.setStartComp(...)` | 入口组件 |
| `workflow.set_end_comp(...)` | `workflow.setEndComp(...)` | 出口组件 |
| `workflow.add_workflow_comp(...)` | `workflow.addWorkflowComp(...)` | 添加中间组件 |
| `workflow.add_connection(...)` | `workflow.addConnection(...)` | 普通边 |
| `workflow.add_stream_connection(...)` | `workflow.addStreamConnection(...)` | 流式边 |
| `inputs_schema` | `inputsSchema` | 可用 `Map.of(...)` 表达 |
| `stream_inputs_schema` | `streamInputsSchema` | 常用于 `End` 收流 |
| `invoke` / `stream` / `transform` / `collect` | `invoke` / `stream` / `transform` / `collect` | 组件能力名基本一致 |

Java 里有两个容易混淆的包：

- `component.*` 是当前主实现包；
- `components.*` 多数是兼容旧路径的包装类型。

新文档和新代码优先看 `component.*`，维护旧示例或旧 API 时再看 `components.*`。

## 开始组件

`Start` 是 workflow 的入口节点，用于接收顶层输入，并按 `inputsSchema` 输出给下游节点。它本身不做业务处理，重点是把“用户输入里的字段”变成图里的第一个节点输出。

```java
Workflow workflow = new Workflow();

workflow.setStartComp(
        "start",
        new Start(),
        Map.of(
                "query", "${inputs.query}",
                "tokens", "${inputs.tokens}"
        )
);
```

上面这段和 Python 文档中的 `inputs_schema={"query": "${user_inputs.query}"}` 是同一个概念：左侧是 `Start` 输出字段，右侧是从工作流输入里取值的表达式。

一个最小 `Start -> End` 工作流通常长这样：

```java
Workflow workflow = new Workflow();
workflow.setStartComp("start", new Start(), Map.of("query", "${inputs.query}"));
workflow.setEndComp("end", new End(), Map.of("answer", "${start.query}"));
workflow.addConnection("start", "end");

WorkflowOutput output = workflow.invoke(
        Map.of("inputs", Map.of("query", "hello world")),
        null,
        null
);
```

## 结束组件

`End` 是 workflow 的出口节点。它负责收敛中间节点输出，生成最终 `WorkflowOutput`。Python 文档里把 `End` 分成“无模板直接输出”和“模板渲染输出”，Java 也支持这两种思路。

直接输出：

```java
workflow.setEndComp("end", new End(), Map.of("answer", "${llm.content}"));
```

模板输出：

```java
workflow.setEndComp(
        "end",
        new End(new EndConfig("最终答案：{{answer}}")),
        Map.of("answer", "${llm.content}")
);
```

`End` 也覆盖 Python 文档里强调的四种组件能力：

| 能力 | Java 方法 | 典型场景 |
| --- | --- | --- |
| 批量调用 | `invoke(...)` | 一次性收敛普通节点输出 |
| 流式输出 | `stream(...)` | 输出可以分块生成 |
| 流式转换 | `transform(...)` | 上游是流式边，下游持续接收 |
| 流式汇聚 | `collect(...)` | 先收集上游流，再生成最终结果 |

流式边示例：

```java
workflow.setEndComp(
        "end",
        new End(new EndConfig("{{result}}")),
        null,
        null,
        Map.of("result", "${streamNode.result}"),
        null,
        "streaming"
);
workflow.addStreamConnection("streamNode", "end");
```

## 大模型组件

Python 文档里的“大模型组件”对应 Java 的 `LLMComponent` 和 `LLMCompConfig`。它适合把一次模型调用包装成 workflow 节点。

`LLMCompConfig` 当前主要字段包括：

| 字段 | 说明 |
| --- | --- |
| `modelId` | 从 Runner 资源管理器中查找模型 |
| `modelClientConfig` | 直接声明模型客户端配置 |
| `modelConfig` | 模型请求配置 |
| `templateContent` | 多段 prompt 模板内容 |
| `systemPromptTemplate` | system message 模板 |
| `userPromptTemplate` | user message 模板 |
| `responseFormat` | 输出格式约束 |
| `outputConfig` | 输出映射配置 |
| `enableHistory` | 是否读取会话历史 |
| `cacheStream` | 是否缓存流式输出 |

典型接法：

```java
LLMCompConfig config = new LLMCompConfig();
config.setModelId("chat-model");
config.setEnableHistory(true);

workflow.addWorkflowComp(
        "llm",
        new LLMComponent(config),
        Map.of("query", "${start.query}"),
        null
);
workflow.addConnection("start", "llm");
```

这里不要照抄 Python 的 `asyncio`、`create_workflow_session` 或 snake_case 方法名。Java 侧的 session 和执行入口以 `Workflow.invoke(...)` / `Workflow.stream(...)`、`Runner.runWorkflow(...)` 为准。

## 提问器组件

`QuestionerComponent` 用于“用户信息不完整时继续追问”。Python 文档强调它能根据字段抽取结果决定是否中断并等待用户补充；Java 当前实现也保留了状态机与 session 恢复主线。

`QuestionerConfig` 常用字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `modelId` | `null` | 使用 Runner 中的模型资源 |
| `responseType` | `reply_directly` | 响应模式 |
| `questionContent` | `""` | 追问内容 |
| `extractFieldsFromResponse` | `true` | 是否从模型回复中抽取字段 |
| `fieldNames` | `[]` | 需要收集的字段 |
| `maxResponse` | `3` | 最大追问次数 |
| `withChatHistory` | `false` | 是否携带历史 |
| `acceptLanguage` | `zh` | 追问语言 |

在 workflow 中，它通常位于业务节点之前，用于补齐参数：

```java
QuestionerConfig config = new QuestionerConfig();
config.setQuestionContent("请补充转账金额");
config.setMaxResponse(3);

workflow.addWorkflowComp(
        "questioner",
        new QuestionerComponent(config),
        Map.of("query", "${start.query}"),
        null
);
```

如果执行过程中触发交互，中断和恢复逻辑应结合 [Session / 中断恢复](../../高阶用法/Session/中断恢复.md) 阅读。

## 意图识别和分支组件

Python 文档把“意图识别组件”和“分支组件”分开讲：先用模型判断意图，再按意图走不同分支。Java 里对应两层：

- `IntentDetectionComponent`：语义层面的意图识别分支组件；
- `IntentDetectionComponentImpl`：当前更适合直接实例化的实现类；
- `BranchComponent` / `BranchRouter`：底层分支路由能力。

常见写法：

```java
IntentDetectionCompConfig config = new IntentDetectionCompConfig();
IntentDetectionComponentImpl detector = new IntentDetectionComponentImpl(config);
detector.addBranch("transfer", "transferFlow");
detector.addBranch("balance", "balanceFlow");

workflow.addWorkflowComp("intent", detector, Map.of("query", "${start.query}"), null);
workflow.addConnection("start", "intent");
```

如果只是按数值、表达式或数组条件分支，可直接看 `BranchComponent`、`BranchRouter` 以及条件组件文档；如果要用 LLM 判断自然语言意图，再用 `IntentDetectionComponentImpl`。

## 知识检索组件

`KnowledgeRetrievalComponent` 对应 Python 文档里的知识库检索节点。它把检索配置封装进 workflow，输出检索文本和带元数据的结果。

`KnowledgeRetrievalCompConfig` 主要字段：

| 字段 | 说明 |
| --- | --- |
| `componentKbConfigs` | 组件级知识库配置列表 |
| `vectorStoreConnectionConfig` | 向量库连接配置 |
| `retrievalConfig` | 检索参数 |
| `modelId` | 用于 query rewrite 或模型辅助检索的模型资源 ID |
| `modelClientConfig` | 直接模型客户端配置 |
| `modelConfig` | 模型请求配置 |

在图里的用法通常是“先检索，再交给 LLM 总结”：

```java
KnowledgeRetrievalCompConfig config = new KnowledgeRetrievalCompConfig();

workflow.addWorkflowComp(
        "retrieval",
        new KnowledgeRetrievalComponent(config),
        Map.of("query", "${start.query}"),
        null
);
workflow.addConnection("start", "retrieval");
```

解析器、chunker、indexer、retriever、reranker 的完整主题不在本页展开，可继续看 [知识检索](../../高阶用法/知识检索.md) 和 API 文档里的 `retrieval` 包。

## 记忆检索和记忆写入组件

Python 文档里记忆组件分成检索和写入。Java 也有两个工作流组件：

| 组件 | 配置 | 作用 |
| --- | --- | --- |
| `MemoryRetrievalComponent` | `MemoryRetrievalCompConfig` | 按 `scopeId`、`userId`、`threshold` 从 `LongTermMemory` 取相关记忆 |
| `MemoryWriteComponent` | `MemoryWriteCompConfig` | 将消息、历史或变量写入 `LongTermMemory` |

检索配置常见字段：

```java
MemoryRetrievalCompConfig config = MemoryRetrievalCompConfig.builder()
        .memory(memory)
        .scopeId("project")
        .userId("user-1")
        .threshold(0.3d)
        .build();
```

写入配置常见字段：

```java
MemoryWriteCompConfig config = MemoryWriteCompConfig.builder()
        .memory(memory)
        .scopeId("project")
        .userId("user-1")
        .sessionId("session-1")
        .genMem(true)
        .genMemWithHistoryMsgNum(2)
        .build();
```

如果你关心 scope、变量记忆、分页、更新和删除，继续看 [记忆引擎](../../高阶用法/记忆引擎.md)。

## 工具组件

`ToolComponent` 用于把 Java `Tool` 接成 workflow 节点。Python 文档里“插件组件 / 工具组件”的主线，在 Java 里对应 `ToolComponentConfig.toolId` 和实际工具绑定。

```java
ToolComponentConfig config = new ToolComponentConfig();
config.setToolId("search_tool");

ToolComponent component = new ToolComponent(config);
component.bindTool(tool);

workflow.addWorkflowComp(
        "tool",
        component,
        Map.of("query", "${start.query}"),
        null
);
```

`ToolComponentInput` / `ToolComponentOutput` 是 DTO；日常搭图时先看 `ToolComponent` 和 `ToolComponentConfig`。

## HTTP 请求组件

HTTP 请求组件位于 `component.tool.http` 子包，入口是 `HTTPRequestComponent` 和 `HttpComponentConfig`。它适合把一个外部 HTTP API 接成 workflow 节点。

`HttpComponentConfig` 当前核心字段是 `requestParams`，对应 `HttpRequestParamConfig`。请求方法、URL、header、body、超时等细节应以该配置类和 API 文档为准。

如果你只是要调用一个已有 Java `Tool`，优先用 `ToolComponent`；如果需求本身就是固定 HTTP API 调用，再使用 `HTTPRequestComponent`。

## 子工作流组件

Python 文档把子工作流写成“把一条已有 workflow 当成父图节点复用”。Java 对应：

- `SubWorkflowComponentImpl`
- 兼容包装 `components.flow.SubWorkflowComponent`

典型形态：

```java
Workflow child = buildChildWorkflow();
SubWorkflowComponent sub = new SubWorkflowComponent(child);

workflow.addWorkflowComp(
        "sub",
        sub,
        Map.of("query", "${start.query}"),
        null
);
```

子工作流适合复用一个稳定流程，比如“检索 + 总结”或“校验 + 审批”。如果只是两个普通节点串联，不需要额外包成子工作流。

## 循环组件

循环组件用于重复执行一段逻辑。Java 当前有两层：

| 类型 | 说明 |
| --- | --- |
| `LoopComponentImpl` | 常用循环组件入口，根据 `LoopGroup` 和输出 schema 组装循环执行 |
| `AdvancedLoopComponentImpl` | 更底层、更灵活的循环控制入口 |
| `components.flow.loop.LoopComponent` | 兼容包装类型 |

如果循环只是“遍历数组并汇总结果”，先看 `LoopComponentImpl`。如果你需要自定义 break 节点、回调或复杂条件，再看 `AdvancedLoopComponentImpl`。

## 不建议当作主入口的类型

Python 文档里会出现很多内部 helper 和 DTO。Java 文档应避免把这些类型写成“第一入口”：

- `*Executable`
- `*Input` / `*Output`
- `QuestionerState`、`QuestionerEvent`、`QuestionerDirectReplyHandler`
- `TemplateProcessor`、`TemplateUtils`
- `ComponentConfig`、`IOConfig`、`NodeConfig`
- `LoopBreakComponent`、`LoopSetVariableComponent`

这些类型适合调试、扩展或读源码时看，不适合作为第一次搭 workflow 的推荐入口。

## 推荐选型顺序

从零搭一条 Java workflow 时，建议按这个顺序：

1. 先固定 `Start` 和 `End`。
2. 需要模型生成时加入 `LLMComponent`。
3. 用户信息不完整时加入 `QuestionerComponent`。
4. 需要检索上下文时加入 `KnowledgeRetrievalComponent` 或 `MemoryRetrievalComponent`。
5. 需要调用外部能力时加入 `ToolComponent` 或 `HTTPRequestComponent`。
6. 需要自然语言路由时加入 `IntentDetectionComponentImpl`。
7. 需要复用整条流程时加入 `SubWorkflowComponent`。
8. 需要重复执行时加入 `LoopComponentImpl`。

## 当前边界

- 不要直接复制 Python 文档里的 `asyncio`、`create_workflow_session`、snake_case 方法名。
- Java 代码示例应使用 `Workflow.setStartComp(...)`、`setEndComp(...)`、`addWorkflowComp(...)`、`addConnection(...)`、`addStreamConnection(...)`。
- 兼容包 `components.*` 主要为旧路径保留；新文档优先指向 `component.*`。
- 内部 helper 和 DTO 应作为补充说明，不应替代组件主入口。
