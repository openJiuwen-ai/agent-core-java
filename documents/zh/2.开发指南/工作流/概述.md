# 概述

Java 版工作流栏目围绕 `com.openjiuwen.core.workflow` 展开。这里的 `Workflow` 不是“带意图路由的完整应用 Agent”，而是**单条可执行工作流图**：你先定义节点、边、输入输出关系，再用 `invoke(...)` 或 `stream(...)` 执行这张图。

如果你准备继续阅读本栏目，建议按 `[概述](概述.md) -> [关键概念](关键概念.md) -> [构建工作流](构建工作流.md)` 的顺序推进。

## 功能定位

在 Java 仓库里，工作流承担的是“**把组件编排成一条可重复执行的图**”这件事。它特别适合下面几类场景：

- 任务步骤相对明确，希望把执行顺序固定下来。
- 不同步骤需要分别接入不同组件，例如 `Start`、`QuestionerComponent`、`LLMComponent`、`End`。
- 某些节点可能触发补充提问，需要暂停后继续同一会话执行。
- 需要把标准批处理执行和流式输出执行分开控制。
- 希望后续继续扩展条件分支、子工作流、循环或可视化能力。

从职责上看，`Workflow` 更像“图运行时”；它关心的是节点如何注册、边如何连接、状态如何在一次执行里传递，而不是多条 workflow 之间如何做业务级选择。

## `Workflow` 和 `WorkflowAgent` 的关系

这两个类型经常会一起出现，但职责不同：

| 类型 | 主要职责 | 适合什么时候用 |
| --- | --- | --- |
| `Workflow` | 定义并执行单条工作流图 | 你已经知道这条流程该怎么走，想精确控制节点、边和执行方式 |
| `WorkflowAgent` | 在应用层注册多条 workflow，并结合提示模板、默认回复和控制器做统一入口 | 你面对的是用户会话入口，需要在多条 workflow 之间做选择 |

可以把它们理解成两层：

1. **工作流层**：先把单条 `Workflow` 搭好。
2. **应用层**：如果需要一个统一的业务入口，再把这些 `Workflow` 交给 `WorkflowAgent.addWorkflows(...)`。

因此，本栏目主干页只聚焦 **单条 workflow 的构建与执行**。`WorkflowAgent` 在这里只作为“工作流的上层宿主”被说明，不展开多工作流跳转细节。

## 能力分层

理解 Java 工作流时，建议按下面四层建立心智模型：

### 1. 图定义层

这一层定义“这张图是什么”：

- `Workflow`：面向用户的主工作流类。
- `WorkflowCard`：工作流元信息，保存 `id`、`name`、`version`、`description`、`inputParams` 等描述信息。

### 2. 组件编排层

这一层定义“图里有哪些节点，以及它们怎么连接”：

- 起止节点：`Start`、`End`
- 业务节点：`QuestionerComponent`、`LLMComponent`、`BranchComponent`、`SubWorkflowComponentImpl` 等
- 连边方式：`addConnection(...)`、`addConditionalConnection(...)`、`addStreamConnection(...)`

### 3. 执行与会话层

这一层定义“这次执行怎么跑、状态怎么带”：

- `WorkflowSessions`：创建工作流会话的门面入口。
- `WorkflowOutput`：`invoke(...)` 的最终返回容器。
- `WorkflowExecutionState`：执行状态，例如 `COMPLETED`、`INPUT_REQUIRED`。
- `WorkflowChunk` / `OutputSchema` / `StreamMode`：流式执行时输出给调用方的数据块和订阅模式。

### 4. 应用集成层

这一层定义“怎么把工作流放进更完整的应用里”：

- `WorkflowAgent`
- `Runner`
- 会话恢复与交互输入能力

如果你只是要先学会“怎么搭一条 workflow”，读完前三层就够了。

## 最小心智模型

先不要把工作流想得太复杂。对多数入门场景，可以把它压缩成 5 步：

1. 用 `WorkflowCard` 给工作流定义身份和输入说明。
2. 新建 `Workflow`。
3. 注册 `Start`、业务组件、`End`。
4. 用普通边、条件边或流式边把节点连起来。
5. 创建 `WorkflowSessions`，然后执行 `invoke(...)` 或 `stream(...)`。

这也是本栏目后两页会不断复用的主线。
