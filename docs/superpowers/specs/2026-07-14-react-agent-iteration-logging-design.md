# ReActAgent 迭代日志设计

## 背景

`ReActAgent#innerInvoke` 的主循环当前没有记录单轮迭代的开始与结束，运行时难以判断代理正在执行第几轮、某轮是否已经退出，以及异常发生在哪一轮。异常分支会继续抛出异常或转换为流式错误结果，但不会留下带堆栈的代理日志。

## 目标

- 每一轮 ReAct 迭代开始时记录 INFO 日志。
- 每一轮 ReAct 迭代退出时记录 INFO 日志，包括正常完成、`break`、`continue` 和异常退出。
- 迭代内发生运行时异常时记录当前轮次、最大轮次和完整异常堆栈。
- 迭代外的 `innerInvoke` 运行时异常记录调用失败日志和完整异常堆栈。
- 自动清理阶段的上下文保存、提交或流关闭异常记录清理失败日志和完整异常堆栈。
- `innerInvoke` 初始化阶段的运行时异常也纳入调用失败日志边界。
- 流式错误结果构建或写回再次失败时，记录独立的二次失败日志和完整异常堆栈。
- 达到最大迭代次数而未完成时记录 ERROR 日志。
- 保持同步调用、流式调用、恢复执行、工具执行及回调的现有返回值和异常处理语义。

## 非目标

- 不新增日志配置项或开关。
- 不调整 ReAct 循环、回调、上下文保存和中断恢复逻辑。
- 不记录用户输入、模型响应、工具参数或工具结果。
- 不修改只读参考项目和 Demo 工程。

## 设计

### 日志通道和格式

统一使用现有的 `Loggers.AGENT`。INFO 和普通 ERROR 采用参数化日志；携带 throwable 的迭代异常消息预先格式化，以兼容当前 `DefaultLogger.exception` 的 SLF4J 异常输出路径，同时让 JUL 镜像获得相同的实际轮次文本。

正常轮次日志：

```text
INFO ReAct iteration 1/5 started
INFO ReAct iteration 1/5 ended
```

迭代异常日志：

```text
ERROR ReAct iteration 1/5 failed
```

迭代异常日志必须携带原始异常及完整堆栈。非迭代阶段的运行时异常记录为：

```text
ERROR ReActAgent invoke failed
```

自动清理阶段的运行时异常单独记录为：

```text
ERROR ReActAgent cleanup failed
```

流式错误结果处理阶段的二次异常单独记录为：

```text
ERROR ReActAgent streaming error handling failed
```

达到最大迭代次数时记录：

```text
ERROR ReActAgent reached max iterations without completion: 5
```

### 控制流

每轮进入循环后先记录开始日志，再以 `try/catch/finally` 包裹现有轮次逻辑：

1. `try` 保留现有模型调用、强制结束、工具调用、外部工具挂起和中断处理。
2. `catch` 记录带轮次的 ERROR 日志和完整堆栈，然后原样重新抛出异常。
3. `finally` 记录结束 INFO 日志，因此所有 `break`、`continue` 和异常路径都会产生结束日志。

外层 `innerInvoke` 异常分支继续负责原有的同步重新抛出和流式错误结果转换。为避免同一异常重复记录，局部状态只标记迭代异常是否已经记录；外层仅在异常发生于迭代之外时记录 `ReActAgent invoke failed`。

最外层自动清理逻辑单独捕获并记录清理异常，然后原样重新抛出。即使此前已经记录过迭代异常，后续清理异常仍作为独立失败记录，避免被迭代异常去重标记遮蔽。

调用级异常边界从 `innerInvoke` 初始化开始覆盖，确保回调上下文、流式标志或输入附加信息初始化失败时仍记录 `ReActAgent invoke failed`，随后保持原样重新抛出。显式的 `initializationComplete` 状态只在流式标志、回调附加信息和输入附加信息全部就绪后置为 `true`；初始化完成前不得转换流式错误结果，也不得执行原本位于初始化之后的自动清理，避免改变异常传播和清理副作用边界。

流式错误转换位于调用级 `catch` 内，因此其构建或写回操作使用独立的嵌套异常边界；二次异常记录 `ReActAgent streaming error handling failed` 后原样重新抛出，不把它误判为原迭代异常的重复日志。

如果循环耗尽且结果仍为空，先记录达到最大迭代次数的 ERROR 日志，再生成现有的 `result_type=error` 结果。

### 日志顺序

正常轮次：

```text
started -> ended
```

异常轮次：

```text
started -> failed -> ended
```

日志只描述生命周期，不改变任何业务分支。

## 测试设计

在现有 `ReActAgent` 单元测试范围内增加日志捕获测试：

1. 模型首轮直接返回答案时，断言依次出现 `started` 和 `ended`，并保持原结果不变。
2. 轮次通过现有提前退出分支结束时，断言仍有且仅有一条对应的结束日志。
3. 模型或轮次逻辑抛出运行时异常时，断言日志顺序为 `started`、`failed`、`ended`，失败日志携带原始异常；同步调用仍异常完成，流式调用仍返回现有错误结果。
4. 输入校验、回调或初始化等迭代外路径抛出运行时异常时，断言记录 `ReActAgent invoke failed` 和原始异常，且不误报轮次失败。
5. 循环耗尽时，断言每一轮都有成对的开始、结束日志，并记录达到最大迭代次数的 ERROR 日志；现有错误结果不变。
6. 自动清理的提交阶段抛出运行时异常时，断言记录 `ReActAgent cleanup failed`、携带原始异常并保持原有重新抛出语义，同时仍执行流关闭。
7. 初始化流式标志时抛出运行时异常，断言记录 `ReActAgent invoke failed` 并原样重新抛出。
8. 原迭代异常转换为流式错误结果时，如果会话写流再次失败，断言原迭代异常和二次写回异常各有一条带原始 throwable 的 ERROR 日志，最终仍抛出二次异常。

测试捕获器在用例结束时移除日志处理器，避免影响其他测试。

## 验收标准

- 每个实际进入的 ReAct 轮次恰好产生一条开始 INFO 和一条结束 INFO。
- 迭代异常恰好产生一条带轮次和完整堆栈的 ERROR 日志，不重复记录调用失败。
- 迭代外运行时异常产生一条带完整堆栈的调用失败 ERROR 日志。
- 自动清理异常产生一条带完整堆栈的清理失败 ERROR 日志。
- 初始化阶段异常产生一条带完整堆栈的调用失败 ERROR 日志。
- 流式错误处理二次异常产生一条带完整堆栈的独立 ERROR 日志。
- 最大迭代次数耗尽产生一条明确的 ERROR 日志。
- 日志不包含用户输入、模型内容、工具参数或工具结果。
- 相关单元测试与目标仓既有测试通过。
